# 머신러닝 설계와 검증 계획

목표는 여행자의 조건을 만족하면서 수요 근거가 있는 지역과 음식점 후보를 찾는 것이다. 확인한 공개 자료에 맞는 주 모델은 월별 지역·업종 수요 예측이다. 장소별 일방문량 모델은 점포 레이블이 추가로 확보되는 경우의 확장이다.

## 현재 구현과 운영형 목표

| 모델 | 현재 코드 | 실제 자료 적용 목표 |
|---|---|---|
| 장소 일수요 | Ridge 회귀, 합성 방문량 | 점포별 일 방문 관측 확보 시 |
| 지역 월수요 | 별도 Ridge 회귀, 합성 예시 | 카드 지역·업종 건수에 적용 |
| 취향 개인화 | 태그 일치 규칙 | 동의한 선택 로그 확보 후 학습 순위화 |
| 이동 수요 | 설계 | 버스 노선·정류소 수요 회귀 |
| 방문 전이 | 설계 | 승인 집계 OD로 전이 확률 |
| 경로 구성 | 빔 검색 | 실제 이동행렬로 제약 최적화 |

## 지도학습 목표

지역 모델의 한 행은 월×지역×업종×측정값이다. 동일한 모델에서 건수·이용자·금액을 섞지 않는다. 초기에는 합산 가능한 카드 이용 건수를 선택한다. 이용자 수의 중복 정의가 불확실하면 성별/연령대 합산을 하지 않는다.

현재 장소 모델은 `log1p(visits)`를 목표로 하고, 장소 one hot, 요일 sin/cos, 연중 sin/cos, 시간 추세를 입력으로 쓴다. Ridge 목적함수는 `Σ(y-Xβ)^2 + αΣβ_j²`이며 절편은 거의 정규화하지 않는다. 고정 α=1은 시제품 설정이다. 운영형의 하이퍼파라미터는 학습 내부의 시간 분할에서만 선택한다.

월별 지역 모델은 지역×업종 그룹, 월 계절성, 추세를 학습한다. 12개월 미만이면 연중 계절성 성능을 주장하지 않는다. 최소 24개월, 가능하면 36개월 이력을 확보하고 코로나·운행 개편·업종코드 변경에 따른 분포 변화를 점검한다. 현재 제공 예시는 전부 합성이다.

후속 비교 모델은 Poisson/Tweedie 회귀와 LightGBM/CatBoost 계열이다. 라이브러리와 버전은 실제 설치·실행 검증 후 고정한다. GPU가 없어도 학습·추론 가능한 표 모델을 우선한다. 복잡한 딥러닝은 데이터 규모와 기준모델 개선이 확인된 후 검토한다.

현재 표준 라이브러리의 장소 one hot 회귀는 소규모 검증용이다. 밀집 행렬을 만들기 때문에 장소 수가 커지면 메모리와 연산량이 급증한다. 수천 개 점포를 학습할 운영형에서는 희소 행렬·그룹 집계·검증된 ML 라이브러리로 바꾸고 실제 규모에서 측정한다. 현재 30개 장소 실행 결과로 대규모 처리 성능을 주장하지 않는다.

## 추천 점수와 경로 목적

현재 장소 후보 점수는 `0.55×예측수요의 후보 내 상대점수 + 0.45×태그일치도`다. 혼잡회피를 선택하면 상대수요 점수를 반전한다. 이 가중치는 가정이며 실험으로 최적화된 값이 아니다. 학습된 수요는 맛·위생·서비스 평점이 아니다.

운영형의 지역 모델 예측을 음식점에 연결할 때에는 `area_demand_score`로 이름을 유지한다. 한 지역의 모든 점포에 같은 수요를 방문량처럼 복사하지 않는다. 지역 점수는 방문 지역 선택에만 쓰고, 음식점 간 순위는 검증된 위치·업종·가격·선호·개별 관측 근거로 만든다.

빔 검색은 방문 효용과 업종 다양성의 합에서 이동시간 비용을 뺀 값을 비교한다. 개별 방문의 개폐점, 체류시간, 모든 구간의 비용, 복귀 구간과 마감시각을 검사한다. 현재 후보 상한 40개, 빔 폭 60, 최대 8개 방문이며 전역 최적해는 보장하지 않는다. 점심·저녁의 필수 식사 슬롯과 하루 이상 일정은 후속 범위다.

## 누수를 막는 시간 검증

현재 일수요 모델은 날짜의 앞 80%로 학습하고 뒤 20%로 검증한다. 같은 날의 서로 다른 장소가 학습/검증 양쪽으로 갈라지지 않는다. 평균 기준모델과 범주 목록은 학습 부분에서만 계산한다. 검증을 마친 배포용 모델은 전체 이력으로 다시 학습한다. 이 모델의 학습 종료일 이후만 추천한다.

이는 1회 시간 검증이며 최종 독립 테스트는 아니다. 실제 개발에서는 마지막 2~3개월을 손대지 않는 테스트로 고정하고 이전 기간에서 3회 이상의 rolling origin 검증을 수행한다. 기준일 당시 공개된 자료만 쓸 수 있도록 공개 지연을 적용한다. 예측 당일의 실제 날씨·현재 월의 완성 집계·전처리에서 전체 기간으로 계산한 평균을 쓰지 않는다.

## 평가 지표

| 평가 대상 | 지표 | 통과 판단 제안 |
|---|---|---|
| 지역 수요 | MAE, WAPE, Poisson deviance | 최소 3개 시점에서 기준모델과 비교 |
| 계절성 | 전월·전년동월·이동평균 대비 | 실데이터 테스트 결과로만 판단 |
| 지역 상위 순위 | 실제 상위 지역 Recall@K 또는 NDCG | 관측 단위 일치, 시점별 분리 |
| 음식점 개인화 | 선택/방문 로그 NDCG@10 | 현재 정답 없어 미측정 |
| 경로 실현성 | 시간·영업·예산·귀환 위반률 | 검증 시나리오에서 위반 0 목표 |
| 근거 | 출처 연결률, 근거와 단위 일치율 | 100% 목표, 실측값 별도 보고 |
| 운용 | CPU 메모리·P50/P95 지연 | 센터 동일 사양에서 측정 |

현재 출력 `metrics.json`의 MAE는 합성 자료에서 계산한 실행 검증값이다. 점수 개선률을 대회의 실제 성능이나 수상 가능성으로 해석하지 않는다. 기준모델을 이기지 못하면 결과를 그대로 보고하고 모델을 선택한다.

## 불확실성과 편향

예측값은 표본 카드사·소비자 구성·계절성·공개 지연의 영향을 받는다. 카드 이용자가 전체 관광객을 대표한다고 단정하지 않는다. 고가 업종은 금액이 크지만 방문자 수가 많다는 뜻이 아니다. 도민 선호를 관광객 선호로 대체하지 않는다.

인기만 최적화하면 쏠림이 커질 수 있다. 가까운 대체 장소, 지역 다양성, 혼잡 회피를 별도 제어하고 추천 점수 구성 요소를 공개한다. 별도 홀드아웃으로 보정하지 않은 수치를 확률이나 신뢰구간으로 표시하지 않는다.

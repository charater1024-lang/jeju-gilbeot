# v4 관광지 슬라이드·지도·위치와 음식 취향 추천

2026-10-28 구현. 센터 PC의 CPU 로컬 앱 범위를 유지했다. 새 화면과 API를 기존 실제 장소 일정·세션 초기화·출처 안내에 연결했다.

## 메인 배너

성산일출봉, 함덕해수욕장(북부), 협재해수욕장, 사려니숲길, 천지연폭포, 섭지코지의 기존 출처 확인 사진 6장을 사용한다. 5초 간격, 이전·다음, 선택 점, 재생·정지와 키보드를 제공한다. 마우스·포커스 조작, 숨겨진 탭, reduced motion을 고려한다. 설정은 config/hero_slides.json이며 허용된 로컬 이미지·출처·앵커를 검증한다. 광고 업로드·관리자 로그인·광고 집행 기능은 현재 구현 범위가 아니다.

## 지도와 위치

기본 Natural Earth 해안선 참고도는 인터넷 없이 장소 좌표를 표시한다. 도로·행정경계·정밀 지형이 없는 참고도이고 작은 섬 일부는 생략된다. 장소를 누르면 이름·출처·좌표를 볼 수 있다. 겹친 점은 결과 카드의 지도에서 보기로 한 곳을 보거나 온라인 지도에서 확대한다.

Leaflet 1.9.4를 로컬에 포함했다. 사용자가 켠 경우에만 OSM 타일을 불러오고 온라인 실패 시 참고도로 복귀한다. 최초 뷰는 제주 전체이며 GPS나 검색 결과에 따라 온라인 뷰를 자동 이동하지 않는다. GPS 마커는 로컬 SVG에만 그린다. 수동 지도 열람은 타일 영역과 IP가 제공자에게 전달된다는 안내를 표시한다. 타일 캐시팩·대량 미리 받기는 하지 않는다.

기기 위치는 명시적 버튼 → 브라우저 권한 → 일회성 getCurrentPosition 순서다. 권한 거절·시간초과·불가능·낮은 정확도·제주 밖을 처리한다. 기기 위치는 GPS 전용이 아니며 OS/네트워크 기반 추정일 수 있다. localhost/loopback 또는 HTTPS 환경이 필요하다. 위치 없이 음식 검색, 제주공항 부근·대표 관광지를 기준으로 거리 계산하는 대안을 제공한다.

## 실데이터와 학습

- 인허가 20,954문서 + 별도 OSM 6,102문서 = 27,056문서. 실제 업소의 중복 없는 개수로 해석하지 않는다.
- TF-IDF 어휘 59,919개, 희소 posting 393,149개. 모델 2,426,064바이트, 검색 DB 21,774,336바이트.
- 이름·업종·주소·관측된 cuisine 태그에서 문서빈도와 IDF, 정규화 벡터를 학습한다. 동의어·연관어와 거리 계산은 별도 규칙이다. 음식 메뉴나 개인 취향 정답을 학습한 모델이 아니다.
- 인허가 ↔ 여행장소의 상호·전체 주소가 일치하는 2건만 좌표 연결. 좌표 없는 인허가 20,952건을 유지하고 보조 목록·주소 지도 검색으로 안내한다.
- OSM은 6,180개 원본 요소에서 이름·좌표 유효 6,102건. 음식 업종 분류와 좌표는 공동 편집 기록이며 현재 영업·메뉴·입구 미검증. cuisine 태그가 있는 743건만 사용하고 없는 5,359건은 채우지 않는다.
- 음식어의 상호 직접 일치 → 상호 연관어 → 업종 → 넓은 cuisine 태그로 구분한다. 같은 단계는 위치 있을 때 거리순, 없을 때 TF-IDF 순이다. 관련 이유를 카드에 표시한다.
- 식당 주변 관광지의 거리는 그 식당 기준이며, 사용자 기준인 경우도 별도로 표시한다. 반경·거리는 직선 참고값이다.

OSM은 허브 식당에 좌표를 강제로 붙이지 않는 독립 출처다. 인허가 원문, 좌표 출처, 스냅샷 시점과 라이선스를 구분한다. OSM 원본과 정규화 자료·ODbL 고지를 보존하며 결과 카드·지도·일정 HTML에 출처 링크를 표시한다.

## 통합과 개인정보

POST /api/discover는 음식명·선택 기준 좌표·지역·반경을 받는다. 요청 좌표를 반환·파일 저장·모델 업데이트·로그 기록하지 않는다. URL에 정밀좌표를 넣지 않는다. 지도나 외부 API에 기기 좌표를 자동 전송하지 않는다. 브라우저·OS 위치 서비스 자체의 외부 연결 여부는 웹앱이 보장하지 않는다.

OSM 일정 추가는 클라이언트 좌표를 믿지 않고 서버의 immutable osm_node/way/relation ID를 검색한다. 섬·산 접근 검토를 동일하게 적용한다. 기존 실제 장소 일정은 직선 보정 이동시간과 제약 탐색이며 도로 경로·입장료·영업·전체 예산을 확정하지 않는다. 일정 HTML에는 OSM 출처·라이선스와 미확인을 내보내고 개인 원점 좌표는 넣지 않는다.

GPS 좌표는 탭 메모리에만 둔다. 위치 지우기·새 여행 시작·pagehide에서 제거하고, 복원된 페이지는 초기화한다. 비동기 요청 세대 번호로 초기화 뒤 늦게 도착한 위치/검색 응답이 이전 상태를 되살리지 못하게 했다. sessionStorage에는 공개 장소 필드만 보관한다. 내려받은 일정 파일은 세션 초기화와 별도로 관리한다.

## 검증 결과

- 공식 휴대용 Python에서 66개 테스트 통과. 14개 신규 발견/좌표/정렬 테스트를 포함한다.
- 로컬 HTTP 통합 요청 18개 통과. 음식 검색·반경·제주 밖·오류 입력·OSM ID 일정 연결·모델/DB 무변경을 확인했다.
- 위치 UI 모의 확인 9개, 일정 HTML 확인 6개 통과. 실제 사용자의 GPS 권한은 개발 도구로 요청/허용하지 않았다.
- 실제 브라우저에서 6슬라이드 자동·수동 전환, 정지, 오프라인 핀, 온라인 타일 12/12 로딩, 음식 검색과 일정 연결 확인. 390px에서 가로 넘침이 없었고 임시 크기 설정을 해제했다.
- 설정의 파일 시각만 캐시할 때 갱신한 배편 제한이 늦게 반영될 수 있는 문제를 발견해 작은 설정 JSON을 매번 읽도록 수정했다. 파일 시각이 같아도 제한 변경을 반영하는 회귀 검증을 포함한다.

# 제주 길벗 서비스 제안서

관광 정보 탐색과 당일 코스 작성

개인 제안   구현 기준 v16   2026년 11월 3일

## 제안 내용

제주 길벗을 제주빅데이터센터 방문자가 관광 정보를 살펴보고 당일 코스를 작성하는 서비스로 제안합니다. 이용자는 지역과 관심 장소를 고른 뒤 출발지, 이용 시간, 복귀 조건을 입력합니다. 서비스는 방문 순서와 함께 장소의 출처와 확인할 사항을 보여주고, 결과를 일정 파일로 저장합니다.

장소 이름을 찾는 일과 실제로 방문할 수 있는지 판단하는 일은 다릅니다. 공개 명부와 지도에 같은 장소가 있더라도 소개의 기준일이나 접근 조건을 함께 살펴야 합니다. 제주 길벗은 자료에 남아 있는 방문 제약을 일정 계산에 반영하도록 만들었습니다. 확인이 필요한 관광지가 포함되면 코스를 완성하지 않고 이유를 알립니다.

개인 개발로 검색, 소비·승차 분석, 자동 코스와 직접 담은 장소의 일정 작성을 구현했습니다. 이번 제출에서는 이 시제품을 센터에서 실행할 수 있도록 정리하고, 장소 정보와 이용 흐름을 검수하겠습니다. 처음 적용할 대상은 센터에서 짧은 여행 일정을 정하려는 이용자입니다. 실제 이용자 조사는 아직 진행하지 않았으며 시범 이용을 통해 이 범위를 확인할 계획입니다.

## 이용자가 가져가는 결과

출처가 연결된 장소 목록과 복귀를 포함한 방문 순서입니다. 원하지 않는 장소는 빼고 다시 추천받을 수 있습니다. 저장한 HTML 일정에도 소개의 출처와 주의사항이 남습니다.

## 센터에 제안하는 활용

관광 명부를 검색하고 소비·승차 집계의 의미를 살펴보는 데이터 활용 사례로 제공합니다. 센터 PC에서 핵심 기능을 실행하도록 구성했으며, 외부 유료 AI 호출이나 신규 GPU 구입을 기본 조건으로 두지 않습니다. 현장 설치와 이용자 검수는 센터와 협의가 필요한 단계입니다.

이용 예시 2쪽   자료와 선별 기준 3쪽   모델 평가 4쪽   구현과 검수 5~7쪽


# 이용자가 코스를 만드는 과정

당일 코스를 정하는 설계 시나리오를 예로 들겠습니다. 이용자가 공개 기준점인 제주공항을 출발·복귀 장소로 확인하고, 자동차로 오전 9시부터 오후 6시까지 제주 북부의 세 곳을 방문하도록 설정합니다. 현재 프로그램은 아래 순서를 반환합니다.

## 검색 결과에서 일정으로 이어지는 동작

관광지 소개를 읽고 출처를 확인한 뒤 자동 코스를 요청하거나 직접 장소를 담습니다. 출발지는 기기 위치 또는 수동 기준점을 명시적으로 적용해야 합니다. 좌표를 입력하지 않았을 때 공항을 임의 적용하지 않습니다. 방문 순서는 체류와 복귀 시간을 포함해 계산하며 최대 여덟 곳까지 구성합니다.

추천된 장소가 마음에 들지 않으면 해당 장소를 제외하고 다시 요청합니다. 직접 담은 장소로 만든 일정은 저장 목록이 바뀌면 폐기합니다. 자동 추천은 검색어가 바뀌면 이전 결과를 폐기합니다. 바뀌기 전 요청의 응답이 늦게 도착해도 새 결과로 표시하지 않습니다.

## 코스를 만들지 않는 경우도 결과로 설명

용머리해안처럼 당일 파도·조수에 따른 출입 조건의 추가 확인이 필요한 장소를 수동으로 담으면 일정 생성을 중단합니다. 화면에는 장소명, 검토 사유와 출처 확인일이 표시됩니다. 이를 현재 폐쇄가 확정됐다는 뜻으로 설명하지 않습니다. 시간이 부족할 때는 이용 시간을 늘리는 등 조건 조정 방법을 안내합니다.

식사 장소는 별도 검색에서 직접 담을 수 있습니다. 음식점 기록은 위치 참고자료로 구분하고, 현재 영업이나 메뉴가 확인됐다고 표시하지 않습니다.


# 제주 자료를 사용하는 방식

소비·승차 분석에는 제주빅데이터센터가 제공하고 제주데이터허브가 배포하는 자료를 사용했습니다. 장소 명부는 지도 기록과 연결해 관광 후보를 찾는 데 씁니다. 같은 원천자료가 여러 플랫폼에 실린 경우 독립 자료로 중복 집계하지 않습니다.

## 관광 후보를 고르는 기준

명부와 지도 이름을 같은 규칙으로 정리한 뒤 정확히 일치하고 좌표가 250m 이내인 기록을 연결했습니다. 분류와 중복을 정리한 68곳을 보존하고, 그중 공식 소개와 출처 기록, 접근 조건 검사를 통과한 40곳에서 정상 코스를 구성합니다. 40곳은 현재 영업이 확인된 관광지 수를 뜻하지 않습니다.

자동 추천과 직접 담은 관광지에 같은 검사를 적용합니다. 기록된 접근 제한, 배편·탐방 입구 확인 필요, 소개 누락 등으로 조건을 통과하지 못하면 사유를 표시합니다. 장소를 이용자에게 알리지 않고 다른 곳으로 대체하지 않습니다.

원본·출처 URL·관측기간·해시와 가공 이력을 보관합니다. 소개 자료는 내부 180일 재검토 기한을 적용합니다. OSM 출처·ODbL 표시를 유지하고, 원자료 제출·반출 조건은 패키지 구성 전 확인하겠습니다.


# 소비와 승차 모델의 평가

소비 모델은 월별 식음료 업종 비중을, 승차 모델은 요일·시간대의 일반 승차 패턴을 추정합니다. 두 결과는 제주 전체의 과거 집계를 이해하는 참고 기능입니다. 개별 점포의 인기나 관광 코스의 만족도를 평가한 수치는 아닙니다.

## 모델을 선택한 방법과 남은 오차

검증 구간에서 설정을 고정한 뒤, 같은 적합 범위의 평균 모형과 비교했습니다. 소비는 최근 자료에 가중치를 준 계절 Ridge, 승차는 큰 이상값의 영향을 줄이는 Huber 회귀를 사용합니다. 운영 모델은 선택 후 전체 실제 관측으로 다시 적합했습니다.

소비 개선의 상당 부분은 최근 경향을 반영한 효과입니다. 한식과 음료 업종은 다른 업종보다 오차가 컸습니다. 승차의 평균오차는 줄었지만 일부 시간대와 검증 지표는 개선되지 않았습니다. 기존에 평가한 과거 구간을 다시 활용한 후향 평가이므로, 새 기간 자료로 성능을 추가 확인해야 합니다.


# Agent의 판단 범위와 실행 환경

제주 길벗의 Agent는 검색과 검증, 경로 계산을 중앙에서 이어 주는 추천 워크플로입니다. 사용자가 확인한 조건으로 도구를 실행하고 결과를 다시 검사합니다. 운영 중 필요한 도구를 자유롭게 선택하거나 외부 정보를 스스로 수집하는 방식은 사용하지 않습니다.

## 모델과 도구의 역할

관광·음식 검색은 실제 자료의 문서 빈도와 문자 표현을 학습한 TF-IDF 모델을 사용합니다. 출처와 방문 제약은 정책 규칙으로 검사하고, 코스는 후보 수와 탐색 폭을 제한해 시간과 이동비 조건을 비교합니다. 소비·승차의 회귀 모델은 분석 화면에 연결돼 있습니다. 상담은 규칙과 준비된 안내문으로 답합니다.

관광 자동 선택은 방문 가능한 장소 수를 먼저 비교하고 같은 수에서는 복귀를 포함한 추정 이동시간과 이동비를 비교합니다. 후보를 최대 24개로 제한하므로 다른 조합에서 더 나은 코스가 나올 수 있습니다. 개인 취향을 별도로 학습한 추천은 아닙니다.

## 센터에서 실행하는 구성

Python 표준 라이브러리와 SQLite, JSON 모델, HTML·CSS·JavaScript로 구성했습니다. 내장 Python과 실행 파일을 제공하며 핵심 검색·분석·일정 계산은 CPU와 로컬 자료로 동작합니다. 유료 API 키와 런타임 생성형 AI를 요구하지 않습니다. 외부 지도를 켜거나 공식 원문을 열 때는 네트워크가 필요합니다.

센터 최소사양은 i7-8700, GTX 1060, RAM 32GB입니다. 이 장비에서의 설치와 응답시간은 별도 검수 대상입니다. 개발 PC의 함수 실행 결과를 센터 실측 성능으로 제시하지 않습니다.

## 정보가 부족할 때의 처리

정책 파일을 읽을 수 없거나 구조·검토일이 잘못되면 추천을 중단합니다. 소개 확인일과 현재 운영 여부는 구분해 표시합니다. 시간 부족, 지원하지 않는 버스 이동, 제외 의도를 해석하지 못한 검색에는 이유와 입력 방법을 안내합니다. 자연어의 복합 조건을 모두 이해한다고 설명하지 않습니다.

실제 입구, 운영시간·휴무·예약·요금, 실시간 교통은 아직 연결되지 않았습니다. 버스 승차 분석이 있어도 운행일·환승·막차 시간표가 없으므로 버스 코스를 만들지 않습니다. 이 항목은 제출 전 검수와 후속 연동을 구분해 관리합니다.

## 공용 PC의 위치와 저장 파일

기기 위치는 이용자가 적용한 뒤 탭 메모리에서 사용합니다. 위치 해제·조건 변경·초기화 시 이전 경로를 무효화하고, 출발지 정밀 좌표는 HTML 일정에서 제외합니다. 이번 검증은 공개 장소 좌표와 모의 위치로 진행했습니다. 실제 브라우저 화면, 센터 PC와 실제 이용자 과제 검증은 아직 완료하지 않았습니다.

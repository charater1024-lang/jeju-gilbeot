# 챗봇의 위치 추천

챗봇은 LLM 없이 기존 의도·테마 규칙과 관광·음식 TF-IDF 검색 모델을 사용한다. 위치가 있으면 원자료 좌표와 직선거리를 계산하고, 반경 20km의 좌표가 있는 기록만 응답한다. 음식 메뉴·맛·현재 영업·방문 인기도를 검증한 추천은 아니다.

## 요청과 동의

- `POST /api/chat`의 기존 `message`, `state`에 요청 시점의 `location: {latitude, longitude, accuracy_m?}`를 선택적으로 전달한다. 좌표는 브라우저에서 위치 사용 설명과 권한 허용을 거친 뒤 전달한다.
- `내 근처 해변 추천`, `주변 고기국수 추천`처럼 주변을 요청했으나 위치가 없으면 서버는 `needs_location: true`와 설명을 반환한다. 이 응답으로 주변 검색을 실행하지 않는다.
- 사용자가 위치를 쓰지 않기로 선택하면 `location_declined: true`를 전달한다. 지역·음식·테마 검색은 계속하며, 가까운 순서나 반경을 적용하지 않았다고 표시한다.
- 위치가 있는 일반 `관광지 추천`, `맛집 추천`은 메뉴를 다시 묻는 대신 해당 위치 주변 후보를 찾는다.
- 지도에서 직접 고른 기준 장소는 `location.source: "manual"`, 기기 위치는 `"device"`로 구분한다. 미제공 시 기존 API와의 호환을 위해 `device`로 처리한다. `label`은 선택 문자열이며 100자 이내로 검증하고 대화 상태에 저장하지 않는다. 수동 기준은 ‘선택한 기준 장소’라고 안내하여 기기 GPS로 오인하지 않도록 한다.

## 계산과 표시

- 위치는 유한한 숫자와 지구 범위를 검증하고 기존 관광·음식 검색의 제주 좌표 범위를 적용한다. 불리언·문자열·NaN·무한대·잘못된 정확도는 거부한다.
- 제주 밖 위치로 `내 근처`를 요청하면 제주 밖이라고 알리고 주변 결과를 제공하지 않는다. 위치 정확도 오차가 5km보다 크면 별도로 알린다.
- 이전 검색의 지역이 남아 있을 때 현재 위치 검색을 막지 않도록 지역 조건을 초기화한다. 질문에 `북부` 등 지역을 직접 쓰면 해당 지역 조건도 적용한다.
- 테마·음식 질의는 기존 관련도 분류를 유지하고 같은 분류에서 직선거리순으로 표시한다. 음식·테마가 없으면 직선거리순이다. 검색 관련도 분류가 다른 결과 사이의 절대 최단거리 순위를 뜻하지 않는다.
- 음식 검색의 좌표 없는 인허가 기록은 주변 결과에 섞지 않는다. 도로 거리·교통·실제 입구·섬 이동·오늘의 영업 여부는 확인하지 않는다.
- `함덕 근처 카페`는 이름으로 적은 장소 기준 요청이다. 기기 위치와 혼동하지 않고 지도에서 해당 기준 장소를 선택하도록 안내한다. 이 버전의 챗봇은 임의의 이름 기준 주변 검색을 자동 실행하지 않는다.

## 위치 보관

좌표는 요청별 거리 계산에서만 사용한다. 서버의 대화 상태·SQLite·모델·로그·파일·브라우저 저장소에 저장하지 않는다. 응답에 사용자의 좌표를 그대로 돌려주지 않는다. 장소 카드의 공개 원자료 좌표와 `distance_km`는 표시한다.

후속 검색 상태의 `nearby`는 위치 사용 여부를 기억하는 불리언이다. 좌표를 포함하지 않으며, `다른 곳 추천`에서도 현재 요청에 위치가 없으면 다시 위치 동의를 요청하거나 위치 없는 검색을 선택하도록 한다.

브라우저 실제 위치 수신 성공 여부는 운영 PC·OS·브라우저 설정에 달려 있다. 자동 검증은 제주공항의 공개 좌표를 시험 입력으로 사용하며 실제 이용자 GPS를 읽지 않는다.

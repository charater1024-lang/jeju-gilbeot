제주 길벗은 센터 방문자가 제주 데이터를 검색하고 근거를 확인한 뒤, 선택한 실제 장소의 방문 순서를 구성하는 서비스입니다. 작동 중인 시제품을 바탕으로 출발지 확인과 일정 구성의 사용성을 보완하고, 센터에서 직접 실행할 수 있는 결과물로 제출하고자 합니다.

제출 범위와 제안자의 책임

제안자는 데이터 처리, 모델 학습, 화면 개발과 실행 문서 작성을 직접 수행합니다. 현재 기능을 안정화하고 출발 기준을 명확히 하는 작업을 우선 완료하겠습니다. 실제 장소 자동 선택은 필수 검수 이후의 확장 과제로 관리하며, 실시간 교통과 인기 경로 학습은 이번 핵심 제출 범위에 포함하지 않습니다.

02 이용자와 서비스 이용 흐름


센터를 방문한 도민과 관광객은 원자료의 열 구조나 분석 코드를 익히지 않고도, 관심 있는 지역과 장소를 찾아볼 수 있어야 합니다. 제주 길벗은 검색 결과에서 출처를 확인하고 마음에 드는 장소를 일정에 담는 흐름으로 이 과정을 구성했습니다.

화면 설명에서 지킬 기준

한 장소의 관광 소개와 지도·명부의 근거를 구분해 보여줍니다. 좌표가 없는 음식점은 거리순 일정에 넣지 않으며, 배편이나 실제 접근 입구가 필요한 장소는 계산을 제한합니다. 위치를 받지 못했을 때는 수동 기준 장소로 탐색할 수 있습니다.

현재 탐색용 위치와 일정 출발점은 자동 연결되지 않습니다. 일정 기본값은 제주공항이며, 출발지 확인 보완은 8쪽의 개발 과제입니다. 근거 [2].

03 현재 제공 기능과 제출 범위


검색·분석·일정 저장은 현재 시제품으로 시연합니다. 출발지 확인과 운영 검수는 제출 전 완료 조건을 두어 관리하고, 확장 기능은 기본 검수가 끝난 뒤 적용 여부를 결정하겠습니다.

일정 결과의 의미

현재 일정은 사용자가 고른 장소를 모두 방문하는 순서를 비교합니다. 이동시간은 좌표 간 거리를 보정한 추정값이고, 비용은 추정 이동비입니다. 실제 영업시간, 입장료와 식사비를 확인한 예약 가능 일정으로 표시하지 않습니다.

한 사람이 완성할 수 있는 범위

기능 수를 늘리기보다 잘못된 출발지 적용, 장소의 오연결, 초기화 실패를 먼저 해결하겠습니다. 자동 장소 선택이 검수 기준을 충족하지 못하면 사용자 선택 방식을 유지한 채 제출 범위를 고정합니다. 지원하지 않는 요청을 분명히 안내하는 동작도 결과물의 일부로 검수합니다.

서비스에서 가상 장소와 합성 데이터 기능을 제거했습니다. 과거 개발 이력은 실행 결과와 실자료 성능에서 제외합니다. 근거 [2].

관광 후보를 채택하는 절차

이름을 같은 규칙으로 정리한 뒤 정확히 일치하는 기록을 찾고, 두 좌표가 250m 이내인지 확인합니다. 음식·숙박·상점·일반시설을 제외한 다음 근접 중복을 정리합니다. 남은 68개는 이 교차확인 규칙을 통과한 후보이며 공식 지정 관광지 수를 뜻하지 않습니다. 표시 이름은 허브명을 우선하고 원래 지도 이름도 보존합니다.

갱신과 이용조건 관리

원본, 출처 URL, 관측기간과 파일 해시를 보존하고 가공·학습 이력을 연결했습니다. 11월 1일 재조회한 소비·승차 공개 CSV는 보관 원본과 같은 파일입니다. 음식 27,056개는 출처 기록의 합계이며 고유 맛집 수가 아닙니다. 원자료 재배포 조건이 미확인인 항목은 제출 전 확인하고, 확인된 범위로 패키지를 구성하겠습니다.

허브512의 설명 기간과 CSV의 실제 행 기간이 달라 위 표에는 실제 학습에 쓴 날짜를 기재했습니다. 근거 [3] 원본 명세, [4] 현재 파일 확인. OSM은 OpenStreetMap contributors 및 ODbL 조건을 유지합니다.

05 소비 경향 모델의 검증 결과


소비 모델은 도민과 내국인 참고 집단에서 어떤 식음료 업종의 이용 비중이 높은지 보여줍니다. 최근 12개월에 더 큰 가중치를 주고 월별 변화를 학습하는 회귀 모델을 적용했습니다. 출력은 업종 구성비이며 개별 음식점의 맛이나 인기 점수가 아닙니다.

그림 2 소비 비중 추정의 허용오차 내 비율 비교 2024년 1월부터 2025년 6월의 288개 업종 셀

| 쉽게 읽는 지표 | 기존 평균 | 개선 모델 |
| --- | --- | --- |
| 비중 오차 1퍼센트포인트 이내 | 158/288  54.9% | 252/288  87.5% |

예를 들어 실제 비중이 20%일 때 19~21%로 추정하면 첫 번째 기준을 충족합니다. 개선 모델은 288개 월·집단·업종 셀 가운데 252개에서 이 범위에 들어왔습니다. 같은 월의 업종 값은 서로 연관돼 있으므로 288명의 독립된 이용자를 시험한 결과로 해석하지 않습니다.

기존 집단별 평균 대비 MAE는 73.26% 줄었습니다. 같은 최근 가중 평균의 허용오차 내 비율도 86.8%로, 개선의 대부분은 최근 분포 반영 효과입니다. 업종별로는 한식 44.4%, 음료점 58.3%가 1퍼센트포인트 기준에 들어와 추가 검토가 필요합니다.

설명용 허용오차를 고정해 계산했으며 현장 합격기준으로 승인된 값은 아닙니다. 모든 비교모형을 같은72개월에 적합했습니다. 기존 과거 테스트 기간을 재사용한 후향 평가입니다. 근거 [5], [6].

06 승차 시간대 모델의 검증 결과


승차 모델은 날짜의 요일과 시간대, 계절적 차이를 반영해 제주 전체의 일반 승차 패턴을 비교합니다. 최근 자료에 가중치를 주고 큰 편차의 영향을 완화하는 Huber 회귀를 사용했습니다. 실제 노선의 혼잡도나 버스 출발시각을 예측하는 기능은 제공하지 않습니다.

실제 시간당 인원이 1,000명일 때 800~1,200명으로 추정하면 20% 기준을 충족합니다. 이번 평가에서는 847개 관측 중 699개가 이 범위에 들어왔습니다. 시간구간별 인원 차이가 크므로 전체 비율과 시간대별 오차를 함께 확인해야 합니다.

평균 절대오차는 6.44% 줄었습니다. 다만 16~18시와 19~21시의 허용오차 내 비율은 소폭 하락했고, 검증 RMSE도 177.67에서 179.28명/시간으로 증가했습니다. 개선되지 않은 구간을 함께 관리하고 새 자료로 다시 검증하겠습니다.

신규·기준모형 모두 동일한 최초430일로 학습해 같은121일을 평가했습니다. 허용오차 비율은 분류 Accuracy나 신뢰확률이 아닙니다. 근거 [5], [6].

07 Agent 구성과 실행 방식


제주 길벗의 Agent는 요청 조건을 확인하고 허용된 검색·분석 도구를 실행한 뒤, 결과와 근거를 돌려주는 로컬 처리 흐름입니다. 사용자가 고른 기능에 따라 관광 검색, 음식 검색, 소비 경향 또는 승차 패턴을 조회합니다. 생성형 AI의 자유 답변에 장소의 사실관계를 맡기지 않습니다.

| 일정 계산 | 선택한 실제 장소의 순서 비교와 제약 검사 | 방문 순서, 추정 시간과 비용 |
| 설명과 상담 | 규칙·준비된 안내문·출처 정보 | 관측 사실, 모형 추정, 미확인 항목 구분 |

판단 권한과 운영 통제

Agent는 준비된 자료를 검색하고 조건에 맞지 않는 요청을 거절할 수 있습니다. 원본 수정, 모델 재학습·전환, 외부 예약·결제를 자동 실행하지 않습니다. 자료 갱신은 개발·운영 절차에서 검증한 뒤 적용합니다. 상담은 규칙과 준비된 문장을 사용하며 실행 중 LLM이나 유료 API 키를 요구하지 않습니다.

구현은 Python 표준 라이브러리, SQLite, JSON 모델, HTML·CSS·JavaScript입니다. 핵심 기능은 CPU와 오프라인 자료로 동작합니다. 근거 [2].

08 개발 일정과 완료 조건


개인 개발의 우선순위는 출발지 오해를 줄이는 일과 실제 자료의 신뢰성을 지키는 일입니다. 새 기능은 검수 기준을 통과한 범위만 시연하겠습니다. 아래 일정은 11월 20일 오전 10시 제출 마감에 맞춘 실행계획이며, 센터 협의가 필요한 시험은 협의 가능 여부에 따라 조정합니다.

| 기간 | 우선 작업 | 완료 확인 방법 |
| --- | --- | --- |
| 11월 2~5일 | 출발지 확인과 위치 실패 대응 | GPS 거절·실패 시 공항을 내 위치로 표시하지 않고 출발 기준을 확인 |
| 11월 6~10일 | 관광 후보 검수와 일정 사용성 | 장소 정체성·입구 관련 문제를 검수표로 관리하고 순서 변경·재계산 확인 |
| 11월 11~15일 | 검색 평가와 운영 시험 | 검색 질문60개 목표, 초기화·오프라인·응답시간 시험 결과 기록 |
| 11월 16~19일 | 배포본 동결과 제출 검수 | 코드·모델·출처·매뉴얼을 같은 버전으로 묶고 새 폴더에서 재실행 |
| 조건 충족 시 | 실제 장소 자동 선택 | 기본 검수 완료 후 거리·시간 조건 평가를 통과한 경우에만 포함 |

책임과 협의 범위

| 주체 | 수행 또는 협의할 내용 |
| --- | --- |
| 개인 제안자 | 데이터 처리, 학습·평가, 화면·서버 개발, 오류 수정, 실행 문서와 결과물 작성 |
| 센터에 협의 요청 | 실행 PC·보안정책 확인, 원자료 이용·반출 조건, 설치 시험과 운영 의견 수렴 가능 여부 |

실행 패키지에는 원본에서 모델과 화면 결과까지 이어지는 명세, 이전 버전으로 복구하는 방법과 다음 이용자를 위한 초기화 절차를 함께 제공합니다. 신규 GPU 구매나 상시 LLM 호출을 기본 운영 전제로 두지 않습니다.

인기 경로 학습과 실시간 교통 연동은 데이터·권한·커버리지 확인 이후의 후속 과제입니다. 근거 [1], [2].

09 운영과 품질 검수


센터 적용 전에는 정상적인 추천 결과뿐 아니라 정보가 없거나 지원하지 않는 조건도 확인해야 합니다. 현재의 자동 검사는 구현 동작의 근거이며, 장소의 현장 정확도나 방문 만족도 측정을 대신하지 않습니다.

| 검수 항목 | 현재 확인한 결과 | 제출 전 확인할 기준 |
| --- | --- | --- |
| 코드와 화면 동작 | Python 176개, UI 14개 파일, JS 문법 8개 통과 | 변경 후 같은 회귀 검사 전체 통과 |
| 로컬 API와 출처 | 44요청·4페이지 통과, 모델·DB 해시 보존 | 새 폴더·오프라인 실행과 버전 일치 |
| 모델 오차 | 같은 평가구간에서 평균 기준보다 MAE 개선 | 새 자료 확보 시 후향 평가와 구분해 재평가 |
| 장소 정보 | 이름·250m 위치·분류 교차확인 | 68후보 전수 검토 목표, 중대한 오연결 수정 후 재검사 |
| 실제 이용과 성능 | 사용자 과제·센터 최소사양 실측은 미완료 | 준비 완료 상태 응답 p95 5초·서버 메모리 6GB 이내 목표, 초기화 후 이전 조건 잔존 0건 |

운영 중 정보가 부족할 때

위치를 받지 못하면 수동 기준 장소를 선택하도록 안내합니다. 좌표 없는 기록은 거리 추천에서 제외하고, 산 정상·섬·미지원 이동수단은 계산을 제한합니다. 시간이 부족하면 성공한 일정처럼 표시하지 않고 조건 조정을 요청합니다. 공식 원문이나 온라인 지도에 연결되지 않아도 기본 로컬 검색은 유지합니다.

공용 PC와 개인정보

탐색 위치는 탭 메모리와 로컬 계산에서 사용하며 사용자 GPS 권한을 자동 허용하지 않습니다. 이용 종료 시 새 여행 시작과 탭 종료로 다음 이용자에게 조건이 남지 않도록 합니다. 저장한 일정 파일은 센터의 파일 보관 절차에 따라 관리합니다. 센터 최소사양은 i7-8700, GTX1060, RAM32GB이며 현장 설치·성능 시험은 별도로 진행할 항목입니다.

현재 자동 검증은 로컬 API와 모의 화면 기준입니다. 센터 PC의 실제 이용·화면 검수는 별도로 진행할 항목입니다. 근거 [1], [2].

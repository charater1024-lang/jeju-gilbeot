# v5 관광·자연 명소 확장과 오프라인 도로 원자료

취득·검증일: 2026-10-28. 고정 제주 영역 `(남 32.9, 서 126.0, 북 33.7, 동 127.0)`에서 공개 OpenStreetMap 원자료를 확보했다. 관광과 도로 각각 1회 조회했으며 재시도·로그인·API 키·사용자 GPS 전송은 없었다. 기존 v4 음식점 6,102곳의 정규화 파일은 수정하지 않았다.

## 1. 실제 확보 결과

| 자료 | 원본 | 사용할 수 있는 내용 |
|---|---:|---|
| 관광·자연·공원·역사 장소 | 737,044 bytes / 1,619요소 | 이름·좌표가 있는 1,138곳의 관측 분류·개별 수정 시각 |
| 차량 도로 후보와 노드 | 34,524,993 bytes / 313,983요소 | way 28,196개, 좌표 node 285,787개, 원본 ID와 노드 연결 순서 |

관광 원본은 이름 없는 481요소를 제외해 정규화했다. 같은 OSM 유형과 ID의 정체성을 보존하며 이름이 같다는 이유로 허브 명부나 다른 OSM 요소와 강제로 합치지 않았다. 현재 영업·관광객 인기도·맛·도로 진입 가능 여부를 검증한 자료는 아니다.

두 응답 모두 HTTP 200 JSON으로 수신됐고, 오류 `remark`가 없으며 `elements` 배열이 유효함을 확인했다. HTML 오류 페이지를 데이터로 취급하지 않았다. 관광 응답 한도는 12MiB, 도로 응답 한도는 64MiB로 정했으며 실제 응답은 그 아래였다.

## 2. 관광지 원자료와 관측 분류

조회문은 `data_raw/osm/jeju_tourism_v5.overpassql`에 원문 보존했다. [Overpass 공식 태그·영역 조회 설명](https://dev.overpass-api.de/overpass-doc/en/criteria/per_tag.html)에 따라 node·way·relation을 조회했다.

```overpassql
[out:json][timeout:45][maxsize:67108864];
(
  nwr["tourism"~"^(attraction|museum|viewpoint|artwork|theme_park|zoo|gallery)$"](32.9,126.0,33.7,127.0);
  nwr["natural"~"^(peak|beach|cave_entrance|volcano)$"](32.9,126.0,33.7,127.0);
  nwr["leisure"~"^(park|garden|nature_reserve)$"](32.9,126.0,33.7,127.0);
  nwr["historic"]["name"](32.9,126.0,33.7,127.0);
);
out meta center;
```

숙박 유형은 관광 필터에 넣지 않았으며, 다른 조건과 겹치더라도 `tourism=hotel/guest_house/hostel/motel/apartment/camp_site/caravan_site/chalet/alpine_hut/wilderness_hut`은 정규화에서 제외한다. 이번 응답에서 이름 결측 이외에 추가 제외된 요소는 없었다. 제주 전체 관광업체 명부의 완전성을 보장하는 조회는 아니다.

| 원본 관측 분류 | 정규화 장소의 해당 분류 수 |
|---|---:|
| `tourism=attraction` | 178 |
| `tourism=museum` | 126 |
| `tourism=viewpoint` | 79 |
| `tourism=theme_park` | 66 |
| `tourism=artwork` | 19 |
| `tourism=gallery` | 14 |
| `tourism=zoo` | 0 |
| `natural=peak` | 402 |
| `natural=beach` | 42 |
| `natural=cave_entrance` | 7 |
| `natural=volcano` | 1 |
| `leisure=park` | 96 |
| `leisure=garden` | 29 |
| `leisure=nature_reserve` | 3 |
| 이름 있는 `historic=*` | monument 24, building 13, memorial 13, archaeological_site 12, heritage_building 10, yes 10 등 |

한 장소에 여러 분류가 있을 수 있어 위 표의 합은 고유 장소 수 1,138과 같지 않다. 실제 원천 태그를 `classifications`와 `observed_tags`에 보존했으며 공인 관광지 등급이나 ML이 검증한 분류라고 표현하지 않는다.

관광 원본의 OSM 유형은 node 951, way 659, relation 9다. node는 지도점, way·relation은 요소 경계상자의 중심 좌표다. 중심은 실제 입구·주차장·도로 접점 또는 폴리곤 내부를 보장하지 않는다. `natural=peak/volcano/cave_entrance` 410곳에는 `requires_access_point=true`를 넣어 차량이 곧바로 도달하는 목적지로 취급하지 않도록 했다. 이 값은 자연 지형 유형에 따른 보수적 계획 정책이며 현장 폐쇄나 법적 통행 제한의 확인값은 아니다.

`current_opening_verified`, `routing_access_verified`, `popularity_verified`, `coordinate_verified`는 모두 false다. 공개 `opening_hours`, `fee`, `access`, `wheelchair`가 있으면 원천 관측 태그로만 남긴다. 운영 시간·가격·무장애 접근을 현재 확인한 사실로 바꾸지 않는다.

## 3. 관광 시점과 정규화 계약

OSM DB 기준 시각은 **2026-10-28T12:14:10Z**다. 모든 정규화 장소에 개별 `individual_edit_timestamp`가 있으며 실제 최소·최대는 **2016-11-27T10:54:33Z ~ 2026-10-27T05:53:33Z**다. 개별 시각은 해당 OSM 요소의 최근 편집 시각이다. 업소 영업 확인일이나 방문량 관측일을 뜻하지 않는다.

정규화 파일은 `data_reference/osm_tourism_places.json`이다. 최상위 `items`에 다음 필드를 제공한다.

- `id`: `osm_tourism_node_<id>` / `osm_tourism_way_<id>` / `osm_tourism_relation_<id>`
- `osm_type`, `osm_id`, `name`, `latitude`, `longitude`, `coordinate_kind`
- `category`, `classifications`, `observed_tags`, 관광·자연·공원·역사 유형별 boolean
- `requires_access_point`, `access_point_flag_basis`, `address`
- `individual_edit_timestamp`, `snapshot_at`, `source_date`
- `source_name`, `source_url`, `source_platform`, `data_license`, `attribution`
- 좌표·현재 영업·경로 접근·인기도의 검증 여부 boolean

정규화 과정에서는 공개 편집자의 사용자명·UID를 파생 장소 테이블에 넣지 않는다. 원본 응답은 `out meta`의 공개 편집 메타데이터를 포함한 채 보존한다. 이 정보는 앱 이용자의 정보와 관계없다.

## 4. 실제 도로 연결 원자료

공식 공개 endpoint `https://overpass-api.de/api/interpreter`에 도로 조회를 한 번 POST했다. 도로 본체와 각 way가 참조하는 노드 전체를 가져왔다. 진출입 연결부를 빠뜨리지 않도록 요청한 차량 도로 분류의 `*_link`도 같은 쿼리에 포함했다. [OSM highway 설명](https://wiki.openstreetmap.org/wiki/Key:highway)은 이 분류를 연결로·램프로 설명한다.

```overpassql
[out:json][timeout:60][maxsize:268435456];
(
  way["highway"~"^(motorway|motorway_link|trunk|trunk_link|primary|primary_link|secondary|secondary_link|tertiary|tertiary_link|unclassified|residential|service|living_street)$"](32.9,126.0,33.7,127.0);
  >;
);
out body qt;
```

| 도로 분류 | way 수 |
|---|---:|
| residential | 12,482 |
| service | 7,372 |
| secondary | 2,444 |
| tertiary | 2,388 |
| unclassified | 2,350 |
| secondary_link | 889 |
| tertiary_link | 191 |
| living_street | 67 |
| primary | 3 |
| primary_link | 10 |

이번 실제 응답에 motorway·trunk 등 나머지 조회 유형은 없었다. 도로 등급이 없다는 것과 제주에 해당 현실 도로 기능이 없다는 것은 다르다. OSM에 관측된 분류를 그대로 기록한다.

way의 노드 참조는 328,127개이며 누락된 참조 노드는 0개다. 좌표 node 285,787개는 모두 유한한 수치다. 실제 좌표 범위는 위도 33.113654~33.5656335, 경도 126.1620245~126.9723305다. 조회 영역을 통과하는 way 전체를 가져오는 방식이므로 일반적으로 참조 노드가 경계 바깥에 있을 수 있다.

접근·방향 제한을 아직 적용하지 않은 무향 후보 연결은 299,931구간, 86개 연결 성분이며 최대 연결 성분은 281,496노드다. 이 숫자는 차량이 합법적으로 이동할 수 있는 그래프의 크기가 아니다. 별도 섬이나 단절된 망을 실제 도로처럼 직선으로 이어서는 안 된다.

## 5. 오프라인 경로를 만들 때 유지할 한계

원본 ID·좌표·way 노드 순서로 실제 도로 기하에 따른 로컬 그래프를 만들 수 있다. 하지만 이 다운로드 자체가 내비게이션을 완성한 것은 아니다.

- 관측 `oneway=yes` 3,395, `no` 169, `-1` 3이며 회전교차로 156개가 있다. [OSM oneway 설명](https://wiki.openstreetmap.org/wiki/Key:oneway)의 역방향·암묵 일방통행도 별도 처리해야 한다.
- access 태그가 있는 way는 109개다. `no` 52, `private` 45, `permit` 3 등이며 차량별 태그와 우선순위가 별도로 있다. [OSM access 설명](https://wiki.openstreetmap.org/wiki/Key:access)에 맞춰 해석해야 한다.
- barrier 태그가 있는 노드는 74개다. gate 36, lift_gate 9, kerb 23 등이 있으며 모든 barrier가 같은 의미는 아니다.
- maxspeed 태그가 있는 way는 433개, 전체의 약 1.54%다. 나머지 구간의 이동 시간을 계산하려면 명시한 기본 속도 가정이 필요하다. 관측 통행시간이나 실시간 교통 예측으로 표현하지 않는다.
- 회전 제한 relation, 페리, 보행 전용 경로는 이번 조회에 없다. [OSM 회전 제한 설명](https://wiki.openstreetmap.org/wiki/Relation:restriction)에서 설명하는 from/via/to 연결과 제한을 검증한 경로가 아니다.

현재 공사·통제·사유지 사용 권한·차량 종류별 제한·요금·출입구는 검증하지 않았다. 데이터가 확보됐다는 이유로 실제 운전 안내나 모든 교통 법규 준수를 보장하지 않는다. 그래프 경로를 찾지 못하면 그 사실을 표시하고 임의 도로를 만들어 연결하지 않는다.

| `data_reference/osm_tourism_places.json` | 1,571,487 | `fc2d04393467f6a332d336fc3db66bb240c14b6f6b85ae7c81b8a4699a3d18f2` |
| `data_raw/osm/jeju_roads_v5.json` | 34,524,993 | `eeebbcac54d8b500cb9f3452c8563774b6b73f1a94433b7a0b1c7d3c6f98f964` |

도로 DB 기준 시각은 **2026-10-28T12:16:18Z**다. 도로는 `out body`를 사용해 개별 편집 시각을 요청하지 않았으므로 이 파일에서 각 도로의 최근 편집일을 주장하지 않는다. 관광·도로 요청 시각, 완료 시각, 원문 쿼리, schema·실제 프로파일은 각각 `jeju_tourism_v5_manifest.json`, `jeju_roads_v5_manifest.json`에 있다. 취득·정규화 방법은 같은 폴더 `acquire_v5.py`에 보존했다. 원본이 이미 있으면 자동 중복 조회를 거절하는 개발용 스크립트이며 앱 실행 중에 호출하지 않는다.

기존 `data_reference/osm_food_places.json`의 SHA-256은 `b6f43b9afda08485039f8fdc58c34037e433e776495170e94d7be7bab1156415`로 유지됐다. 이번 추가 자료를 음식점 인허가의 좌표라고 대체하거나 기존 원천 ID로 위장하지 않았다.

## 7. 공개 서버 이용과 라이선스

[Overpass 공식 공유 자원 정책](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)에 따라 고정 제주 영역 두 종류의 스냅샷만 취득했다. 공개 서버는 혼잡·쿼터·거부 가능성이 있으며 사용량이나 제공을 보장하지 않는다. 앱의 사용자별 요청을 이 서버에 전달하거나 자동 반복·대량 미리 읽기로 사용하지 않는다. 정밀 사용자 좌표나 선호는 취득 쿼리에 들어가지 않았다.

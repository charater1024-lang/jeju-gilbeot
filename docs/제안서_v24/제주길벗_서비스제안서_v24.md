# 제주 길벗 서비스 제안서

제주 관광 정보 탐색과 당일 코스 작성

개인 제안   2026년 11월 6일

## 제안 내용

제주 길벗은 제주빅데이터센터를 찾은 도민과 방문객이 공개 자료에서 방문지를 고르고 당일 일정을 작성하는 서비스입니다. 이용자는 출발지와 복귀 시각을 확인하고, 지역과 관심 주제를 선택합니다. 제주 길벗은 후보를 검색하고 자료의 출처와 방문 제약을 검사한 뒤, 주어진 시간에 맞는 방문 순서를 제안합니다. 결과는 장소별 근거와 확인할 사항을 포함한 HTML 일정으로 가져갈 수 있습니다.

여행을 준비할 때 같은 이름의 장소가 지도와 명부에서 다르게 표시되거나, 소개가 있어도 실제 방문 조건이 명확하지 않은 일이 있습니다. 제주 길벗은 이름·위치·분류가 맞는 기록을 먼저 연결하고, 안내 기준일과 접근 조건을 일정 계산에 반영합니다. 확인이 필요한 장소가 포함되면 장소명과 사유를 보여주어 이용자가 입력을 고칠 수 있게 합니다.

## 센터에서의 활용

공개 자료 탐색, 공식 관광 소개 검색, 소비 구성비 조회, 코스 계산을 한 화면 흐름에서 이용할 수 있습니다. 사용자가 장소를 직접 담거나 조건에 맞는 코스를 만들고, 선택을 바꿔 다시 계산할 수 있습니다. 제주 데이터가 어떤 방식으로 여행 결정에 쓰였는지도 결과에서 확인할 수 있습니다.

핵심 기능은 내장 Python, 로컬 SQLite와 저장된 모델로 실행합니다. 일정을 한 건 만들기 위해 외부 생성형 AI 서비스에 요청을 보낼 필요가 없어, 운영자는 API 키 발급과 호출 요금 관리를 줄일 수 있습니다. 장소의 운영 정보가 바뀌면 근거와 정책을 갱신하고, 계산 문제가 생기면 요청이 어느 단계에서 멈췄는지 확인할 수 있습니다.

개인 제안자가 자료 수집과 가공, 학습과 검증, 화면과 서버 구현, 실행 문서를 담당합니다. 센터에는 장비와 보안정책에 맞는 설치 시험, 공개 자료 이용조건, 시범 이용 과제 검수를 협의하겠습니다.

이용 예시 2쪽   데이터 3쪽   모델 4쪽   Agent 구성 5쪽   실행 검증 6쪽   유지보수 7쪽   제출 준비 8쪽

# 이용자가 일정을 만드는 과정

처음 온 이용자는 데이터 안내의 센터 체험 경로에서 공식 관광지 소개 찾기, 외식업종 비교, 자동 일정 작성 중 필요한 기능을 고릅니다. 장소 카드의 명부와 지도 근거를 확인해 원하는 장소를 담거나, 확인된 후보 중에서 조건에 맞는 코스를 계산할 수 있습니다.

## 실행 예시

제주공항 공개 기준점을 적용하고, 북부·자동차·최대 3곳·09:00~18:00·예산 10만원을 선택했습니다. v23 서버의 응답은 용두암 → 탑동광장 → 제주목관아 순서였고, 13:49 공항 복귀를 계산했습니다. 이동비는 2,394원으로 추정했으며, 장소별 요금이 확인되기 전까지 예산 충족 여부는 보류했습니다.

![제주공항 출발과 복귀를 포함한 실제 서비스 응답의 방문 순서](figures/route_example.png)

직접 일정 화면의 예시 조건은 날짜·시간·이동수단·예산 등 입력을 채웁니다. 이용자가 출발지를 따로 적용하고 계산을 눌러야 일정이 만들어집니다.

| 이용자 입력 | 서비스 처리 | 이용자가 확인하는 것 |
| --- | --- | --- |
| 지역·주제 또는 직접 담은 장소 | 명부 조건으로 검색하고 후보의 출처와 방문 제약 확인 | 장소별 출처와 확인일, 제외 사유 |
| 출발지 적용·이용 시간·복귀 조건 | 체류 및 추정 이동 시간을 합산해 가능한 순서 비교 | 방문 순서, 복귀 예정, 추정 이동시간 |
| 장소 제외·조건 수정·저장 | 바뀐 조건으로 재계산하고 이전 결과를 무효화 | 새 일정과 HTML에 남는 근거·주의사항 |

## 결과를 보류하는 경우

출발지를 명시적으로 적용하지 않았거나, 방문 조건 확인이 필요한 장소가 포함되면 다음 행동을 안내합니다. 예를 들어 파도와 조수에 따라 접근 조건을 확인해야 하는 용머리해안은 해당 사유를 보여줍니다. 사용자가 확인할 항목과 자료 기준일을 제시해 일정 작성의 근거를 남깁니다.

이동시간과 이동비는 계획용 추정치입니다. 실제 운행, 입장료, 식사와 주차 등 현장에서 확인할 사항을 결과에 구분합니다. 음식점은 이용자가 검색해 직접 선택할 수 있습니다.

## 장소 기록을 일정에 넣는 기준

관광지의 표시명은 교차 확인한 제주데이터허브 기록을 우선하고 원래 지도명과 근거를 함께 유지합니다. 기존 정책에서 출처와 접근 조건을 통과한 관광 후보 40곳을 코스 계산에 사용합니다. 자동 추천과 직접 담은 관광지에 같은 검사를 적용합니다.

좌표가 없는 음식점 인허가 기록은 이름이나 업종으로 찾을 수 있으며, 거리 계산에는 좌표가 확인된 자료만 쓰입니다. 두 음식 출처의 27,056개는 출처별 기록 합계입니다. 식당의 고유 개수, 최신 영업 여부와 인기도는 별도의 자료가 필요합니다.

## 승인된 관측 자료를 확인하는 방법

공개 1048과 같은 구조의 CSV를 이용자가 선택하면 브라우저에서 지정한 월과 집단의 8업종 관측 건수와 구성비를 계산합니다. 파일의 열·중복·누락을 확인하고, 계산한 관측값을 표로 표시합니다. 공개 1048 파일에서 2025년 6월 제주도민의 8업종 이용건수 785,479건을 확인했습니다. 입력 파일과 집계는 탭에서만 다루고 서버에 전송하거나 학습에 반영하지 않습니다.

# 운영 모델과 평가 범위

화면에 쓰이는 학습 기능은 집단별 소비 구성비와 세부 외식업종 구성비, 공식 관광지 소개 검색입니다. 모델 평가에서는 고정한 과거 관측의 허용오차와 작성 질의의 채점 기준을 구분합니다.

| 운영 기능 | 관측 또는 질의 기준 | 고정 평가 결과 |
| --- | --- | --- |
| 집단별 소비 구성비 | 2024년 1월~2025년 6월의 288셀, ±1퍼센트포인트 | 252/288 → 270/288, 87.50% → 93.75%. 평균 절대오차 0.426 → 0.328퍼센트포인트 |
| 세부 외식업종 구성비 | 2023년 1월~2024년 12월 중 관측된 21개월, 1,974셀, ±0.25퍼센트포인트 | 1,790/1,974, 90.68%. 평균 절대오차 0.097퍼센트포인트 |
| 공식 관광지 소개 검색 | 동결된 작성 질의 22건. 정답의 첫 결과 또는 미지원 질의의 빈 결과 | 22/22. 실제 이용자 평가와 구분 |

집단별 소비 모델은 공통 계절성과 완만한 추세를 조합한 96개 후보 가운데 시간순 검증으로 설정을 골랐습니다. 선정한 모델을 2023년 12월까지의 자료로 적합해 기존 288셀 시험에서 평가한 뒤, 전체 관측에 다시 적합해 배포했습니다. 이미 보고한 시험을 다시 쓴 후향 평가이며 새 관측을 통한 독립 검증은 후속 과제입니다.

예를 들어 실제 업종 비중이 20%라면 19~21%를 ±1퍼센트포인트 안의 결과로 셉니다. 외식업종 중 관측 비중이 큰 10개 업종의 평균 절대오차는 0.490퍼센트포인트입니다. 소비 화면의 수치는 제주 전체를 집계한 참고자료입니다.

## 운영에서 제외한 기능

기존 고정 시험에서 시간대별 승차 82.53%, 노선코드별 승차 48.18%를 기록해 두 예측을 공개 화면과 API에서 제외했습니다. 일정을 만드는 출발지와 시간은 이용자가 직접 확인하도록 바꾸었습니다. 장소와 여행 자료는 검증한 명부에서 조건으로 찾을 수 있습니다. 이전 모델과 평가 파일은 재현 검증용으로 보관합니다. [7]

# 통합 Agent와 실행 구성

일정을 요청하면 서버가 입력 확인, 자료 검색, 후보 검증, 코스 계산, 결과 설명을 순서대로 조정합니다. 하나의 요청 안에서 검색 결과를 계산에 넘기고, 방문 제약과 복귀 조건을 다시 검사합니다. 중간에 판단 근거가 부족하면 해당 단계에서 멈춥니다.

![일정 요청에 따라 Agent가 실행하는 다섯 단계](figures/agent_workflow.png)

## 학습 기능과 판단 규칙의 분담

소비는 계절성을 반영한 Ridge 회귀를 사용합니다. 공식 소개 검색에는 TF-IDF를 적용해 작성된 질의에 관련 근거를 찾습니다. 코스 작성에서는 명부 조건으로 장소를 모으고, 출처 정책과 접근 조건을 확인한 뒤 제한된 후보 안에서 체류 시간과 복귀를 비교합니다. 상담은 준비된 안내문과 규칙을 사용합니다. 도구 실행 범위는 서버의 워크플로에 정해져 있습니다.

## 현장 실행에 필요한 구성

서버는 Windows PC에서 내장 Python 표준 라이브러리로 시작합니다. 장소 자료는 SQLite, 추정 설정은 저장된 JSON 파일을 읽습니다. 브라우저는 로컬 서버에 연결합니다. 일반 탐색, 분석, 코스 계산에는 외부 LLM API와 GPU 추론이 필요하지 않습니다. 기본 실행에 필요한 외부 주소는 없으며, 온라인 지도 타일(`tile.openstreetmap.org`)과 명부의 원문 링크는 이용자가 열 때만 연결합니다. [1]

이 구성에서는 운영 모델이 바뀌어도 웹 화면의 입력 계약과 출처 검사를 유지할 수 있습니다. 운영자가 서비스에서 호출되는 모델과 과거 검증용 후보를 구분할 수 있도록 버전별 파일과 평가 기록을 남깁니다. 배포 시 키나 외부 요청 할당량을 맞출 작업이 줄고, 외부 AI 호출의 건당 비용도 발생하지 않습니다.

| 4 | 200 / 200 | 0.89초 | 0.95초 | 206.8 MiB |
| 8 | 200 / 200 | 1.70초 | 1.85초 | 216.3 MiB |

p95가 1.70초이면 요청 100건 중 약 95건이 1.70초 안에 응답했다는 뜻입니다. 로컬 HTTP 응답 전체 수신까지 측정했으며, 화면 렌더링과 선택형 외부 지도는 범위에서 제외했습니다. 메모리는 Windows 서버 프로세스의 단계 종료 시 누적 최대 작업 집합입니다.

## 검증 범위

v23의 회귀 검사는 Python 301건과 HTTP 42건을 통과했습니다. 실제 브라우저에서 운영 모델 평가, 외식업종 조회, 공식 관광지 소개 검색과 직접 일정 입력의 연결을 확인했습니다. 검증에 사용한 출발점은 공개 장소 좌표입니다. 코드와 데이터의 무결성은 서비스 매니페스트로 확인합니다. [7]

측정 대상은 개발 PC 안에서 서버와 주고받은 HTTP 요청입니다. 센터에서는 설치와 보안정책을 확인한 뒤, 공용 PC에서 브라우저를 사용하는 조건으로 같은 과제를 다시 실행하겠습니다.

# 유지보수와 센터 탑재 계획

설치·조회·계산에서 문제가 생기면 원인을 좁히고 이전 확인본을 복원할 수 있도록 자료와 모델의 변경 이력, 실행 절차를 함께 넘기겠습니다.

| 관리 작업 | 절차 | 확인할 증거 |
| --- | --- | --- |
| 설치와 초기 실행 | 승인된 폴더에서 내장 런타임 실행 후 로컬 주소 접속 | 환경·실행 안내, 주요 화면과 실패 안내 |
| 원본 갱신 | 기준일과 이용조건 확인 후 원본 보존 및 가공 | 원본·가공본 해시, 생성 절차, 사용 범위 |
| 모델 교체 | 시간순 검증으로 후보 선택 후 고정 시험에서 오차 비교 | 기준, 선택 기록, 운영 모델, 검증 결과 |
| 장애와 복구 | 조회와 일정 검증에 실패하면 마지막 확인본 복원 | 매니페스트, 실패 사유, 복구 확인 기록 |

대회가 안내한 센터 환경은 Windows 11, Chrome 또는 Edge, FHD 화면이며 최소사양은 Intel Core i7-8700, GTX 1060, RAM 32GB입니다. 센터는 DLP를 적용하며 일부 외부 주소를 차단합니다. 실제 센터 PC에서는 설치·응답시간과 공용 브라우저 초기화를 확인하겠습니다. 데이터 안내의 로컬 상태 확인 기능으로 시작 단계의 연결을 점검할 수 있습니다. [1]

공용 PC에서 이용자가 적용한 기기 위치는 탭 메모리에 유지하며 일정 요청에 사용합니다. 이용자 초기화 또는 조건 변경 시 이전 일정 결과를 무효화하고, 저장한 일정에서 출발지 정밀 좌표를 제외합니다. 지도에서 제주공항 등 공개 기준점을 선택할 수도 있습니다.

# 제출 산출물과 확인 자료

2026년 11월 20일 오전 10시까지 기획서 PDF와 최종 ZIP을 제출합니다. 최종 점수는 전문가 심사 70%, 참가자 상호평가 30%입니다. 상호평가는 15쪽 이내의 기획서 PDF를 바탕으로 하며 전문가 심사에서는 ZIP으로 실제 실행을 확인합니다. [1]

## 운영진 안내를 반영한 제출 원칙

센터에는 로컬 서버와 브라우저로 설치합니다. 센터 자료는 승인된 파일로 받고, 공개 허브 자료와 대회 별도 제공 자료를 구분합니다. 별도 제공 원본과 이를 담은 DB는 제출 ZIP과 GitHub에서 제외합니다. 공개 자료의 이용조건을 확인하고 OSM ODbL 표시를 유지하며, 외부 접속 주소를 설계서에 적겠습니다. [1]

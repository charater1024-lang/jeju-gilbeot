# 위치 동의와 브라우저 설정

## 먼저 사용하는 순서

1. 서버를 실행한 PC에서 **http://127.0.0.1:8765/** 를 엽니다.
2. 관광지·먹거리 화면의 **내 위치 사용**을 누릅니다.
3. 사이트의 이용 안내를 읽고 **동의하고 위치 요청**을 선택합니다.
4. 브라우저가 위치 권한을 물으면 사용자가 **허용**을 선택합니다.
5. 수신에 성공하면 제주 권역의 주변 관광지·먹거리 직선거리 검색에 사용합니다. 제주 밖이면 제주공항·대표 관광지를 기준 장소로 선택합니다.

사이트의 이용 확인창과 브라우저 권한창은 서로 다른 단계입니다. 사이트가 브라우저의 차단 결정을 강제로 바꾸거나 Windows 위치 서비스를 켤 수는 없습니다. 허용하지 않아도 기본 관광·먹거리 검색과 기준 장소 선택은 사용할 수 있습니다.

## 브라우저 팝업이 나오지 않을 때

**위치 상태 확인**에서 현재 사이트 주소, 보안 환경, 위치 API, 권한과 문서 정책을 확인합니다. 권한 상태 확인 자체는 현재 좌표를 읽는 동작이 아닙니다.

| 표시·현상 | 의미와 다음 행동 |
|---|---|
| `prompt` / 선택 필요 | 아직 브라우저 결정이 필요합니다. 사이트 안내에서 요청한 뒤 주소창 주변의 권한 요청 표시를 확인합니다. |
| `granted` / 허용 | 이전에 허용한 상태라 새 팝업이 생략될 수 있습니다. 이것만으로 좌표 수신 성공을 뜻하지는 않습니다. |
| `denied` / 차단 | 사이트 권한·브라우저 설정·문서 정책 등에서 막힐 수 있습니다. 아래 설정과 진단을 확인합니다. |
| 권한 확인 불가 | Permissions API를 지원하지 않거나 조회할 수 없는 환경일 수 있습니다. 실제 위치 요청 가능 여부와는 별개입니다. |
| 문서 정책 차단 | 포함된 페이지의 `Permissions-Policy`나 상위 프레임 권한에 의해 막힐 수 있습니다. 일반 Chrome/Edge 창에서 같은 주소로 비교합니다. |
| 위치를 사용할 수 없음 (`POSITION_UNAVAILABLE`, 코드 2) | 허용 여부와 별개로 위치 제공자가 좌표를 구하지 못했습니다. OS 위치 서비스·연결 환경을 확인하거나 기준 장소를 사용합니다. |
| 시간 초과 (`TIMEOUT`, 코드 3) | 지정 시간 안에 위치를 받지 못했습니다. 다시 요청하거나 기준 장소로 검색합니다. |

거부 오류인 코드 1 (`PERMISSION_DENIED`)만으로 사용자가 직접 거부했다고 단정할 수 없습니다. 보안 환경이나 문서 정책도 확인해야 합니다. 앱 안의 브라우저가 위치를 지원하지 않는다고 미리 단정하지 않고, 일반 브라우저에서 같은 사이트를 열어 차이를 확인합니다.

## Chrome / Edge에서 사이트 권한 확인

**Chrome:** 해당 사이트를 연 상태에서 주소창 왼쪽 사이트 정보/제어 아이콘 → 사이트 설정 → 위치를 확인합니다. 전체 설정은 **설정 → 개인 정보 보호 및 보안 → 사이트 설정 → 위치**입니다. 차단되어 있다면 사용자가 요청/허용으로 변경한 뒤 사이트에서 다시 요청합니다.

**Edge:** 주소창 왼쪽 사이트 정보 아이콘 → **이 사이트에 대한 사용 권한 → 위치**에서 요청·허용·차단을 확인합니다. 전체 설정은 **설정 → 개인 정보, 검색 및 서비스 → 사이트 사용 권한 → 모든 사용 권한 → 위치**입니다. 브라우저 버전에 따라 메뉴 표현은 조금 다를 수 있습니다.

`http://127.0.0.1:8765`와 `http://localhost:8765`는 같은 PC를 가리켜도 호스트 이름이 다른 출처(origin)입니다. 권한을 확인한 주소와 실제 접속 주소를 맞추세요. 포트가 바뀌어도 출처가 달라집니다.

## Windows 위치 서비스 확인

- **Windows 11:** 시작 → 설정 → 개인 정보 및 보안 → 위치에서 위치 서비스와 앱 위치 접근을 확인합니다.
- **Windows 10:** 시작 → 설정 → 개인 정보 → 위치에서 이 장치의 위치 접근과 앱 위치 접근을 확인합니다. 표시되는 경우 데스크톱 앱의 위치 접근 설정도 확인합니다.

기관 관리 PC에서 설정이 잠겼다면 관리자 정책을 확인해야 합니다. 이 앱은 OS·브라우저 설정을 자동으로 변경하지 않습니다.

## GPS·오프라인·주소의 차이

웹의 Geolocation API는 GPS 수신기만 사용하는 기능이 아닙니다. 기기와 제공자에 따라 Wi-Fi·IP·GPS 등으로 추정한 좌표를 받을 수 있으며 PC에서는 수신 실패나 낮은 정확도가 생길 수 있습니다. 브라우저 허용은 좌표 확보나 정확도의 보장이 아닙니다.

이 앱의 로컬 검색·모델 추론·기본 지도는 오프라인 실행이 가능하지만, 브라우저/OS가 위치를 추정하는 과정에는 네트워크가 필요할 수 있습니다. Chrome은 위치 추정을 위해 Google 위치 서비스를 사용할 수 있습니다. 온라인 연결이 없거나 위치 제공자가 응답하지 않으면 **거리 계산의 기준 장소**를 직접 고르는 방식으로 사용합니다.

위치 API는 보안 환경이 필요합니다. HTTPS와 로컬 루프백 주소인 `localhost`·`127.0.0.1`은 일반적으로 신뢰 가능한 환경으로 취급되지만, 프레임에 포함된 경우 상위 환경도 영향을 줄 수 있습니다. 다른 기기에서 `http://192.168.x.x` 같은 LAN 주소로 여는 것을 localhost와 동일하게 취급해서는 안 됩니다.

실제 기기 위치를 자동으로 요청하거나, 외부 IP 위치 API로 대신 수집하는 방식은 사용하지 않습니다. 실제 좌표 수신·기기 정확도는 사용자가 동의한 기기 환경에서 확인해야 하며, 모의 테스트의 성공을 실제 GPS 수신 성공으로 표시하지 않습니다. 이 안내는 서비스의 사용 흐름이며 법적 동의 요건 충족 여부를 판정하는 문서가 아닙니다.

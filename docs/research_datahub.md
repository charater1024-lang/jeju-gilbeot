# 제주데이터허브 활용 조사

조사일은 2026년 10월 26일이다. 이 자료는 여행 추천 시스템의 데이터 확보 가능성을 판단하기 위한 조사 메모이며, 원본 다운로드나 API 호출이 완료되었다는 의미는 아니다.

## 조사 결론

제주데이터허브의 카드 소비 통계와 버스 수요 통계를 여행 추천의 핵심 입력으로 설계할 수 있다. 다만 확인된 공개 통계는 지역·업종·시간대·노선·정류소별 집계다. 이것만으로 개별 음식점의 실제 방문자 수나 개인별 관광지 방문 순서가 있다고 가정하면 안 된다. 음식점 목록은 상호와 영업상태를 확보하는 기준정보이며 인기도의 정답 레이블은 아니다. 상권 소비 통계로 지역 인기도를 학습하고, 음식점은 위치·업종·영업상태·사용자 조건으로 후보를 정렬하는 현실적인 1차 구현을 권한다.

제주데이터허브 원문 페이지와 파일은 이번 조사 환경에서 WAF 차단 또는 접속 오류가 발생했다. 우회하지 않았으며, 제주특별자치도가 공공데이터포털에 등록한 연결형 API 메타데이터와 교육부 교육데이터 활용지원 서비스의 연계 메타데이터를 함께 확인했다. 실제 원본의 열 이름·코드값·집계 기간·API 인증 규칙은 다운로드 후 확정해야 한다. 공공데이터포털에 표시된 수정일은 관측자료의 최신일이 아니다. `업데이트 주기 실시간`도 실시간 혼잡도 제공을 증명하지 않는다.

## 검증 수준

- A는 제주특별자치도 제공 공공데이터포털 상세 페이지를 직접 읽은 항목이다.
- B는 교육부의 공식 연계 메타데이터에서 허브 원문 URL과 설명을 확인한 항목이다. 허브 원본 자체를 읽지는 못했다.
- C는 연관 데이터 링크에서 후보를 발견했으나 상세 메타데이터를 확인하지 못한 항목이다.
- 모든 항목은 원자료 미취득 상태다. 활용 가능성과 실제 이용 가능 상태를 구분한다.

## 우선 데이터 목록

### H01 내국인 관광객 지역 업종 성별 연령대별 카드 이용 데이터

- 수준 A. 허브 후보 원문은 [597번 데이터](https://www.jejudatahub.net/data/view/data/597), 직접 검증한 공공데이터포털은 [15094857](https://www.data.go.kr/data/15094857/openapi.do)다.
- 공식 설명상 월 단위 소비 집계이며 지역·업종·관광객 구분·연령·성별·이용자 수·횟수·이용액을 포함한다. 이는 설명에 제시된 논리적 필드이며 실제 JSON 키를 확인한 것은 아니다.
- 제공 형식 LINK와 JSON, 무료, 이용허락범위 제한 없음, 개발 자동승인·운영 심의승인이 표시되어 있다. 상세 관측 시작일·종료일은 공란이다. 등록일 2021년 11월 17일, 메타데이터 수정일 2026년 10월 15일.
- 활용: 읍면동별 관광객 식음료 수요와 도민 대비 소비 비중을 학습한다. 특정 음식점 인기도로 바꾸지 않는다. [공식 상세](https://www.data.go.kr/data/15094857/openapi.do)

### H02 관광지 및 상업지구 이용자 유형별 카드 데이터

- 수준 A. [허브 604](https://www.jejudatahub.net/data/view/data/604), [공공데이터포털 15094889](https://www.data.go.kr/data/15094889/openapi.do).

- LINK/JSON, 무료, 이용허락범위 제한 없음, 개발 자동승인·운영 심의승인. 시간 범위는 미기재. 등록 2021년 11월 17일, 메타데이터 수정 2026년 10월 15일.
- 활용: 여행객 소비가 높은 지역과 도민 이용 지역의 선택지를 구분한다. 개인의 출신·국적을 추론하는 용도로 쓰지 않는다. [공식 상세](https://www.data.go.kr/data/15094889/openapi.do)

### H03 관광지 및 상업지구 업종별 카드 데이터

- 수준 A. [허브 605](https://www.jejudatahub.net/data/view/data/605), [공공데이터포털 15094890](https://www.data.go.kr/data/15094890/openapi.do).

- LINK/JSON, 무료, 이용허락범위 제한 없음, 개발 자동승인·운영 심의승인. 관측 기간 미기재. 등록/메타데이터 수정 2021년 11월 17일.
- 활용: 관광지 주변 식음료 소비 강도와 업종 다양성을 특징으로 만든다. 현재 시점의 상권 크기라고 표시하기 전에 관측일을 점검한다. [공식 상세](https://www.data.go.kr/data/15094890/openapi.do)

### H04 관광지 및 상업지구 시간대별 카드 데이터

- 수준 A. [허브 후보 607](https://www.jejudatahub.net/data/view/data/607), [공공데이터포털 15094892](https://www.data.go.kr/data/15094892/openapi.do).
- 공식 설명상 시간대 범주는 밤·오전·오후·저녁·점심이다. 1시간 단위라고 가정할 수 없다. 집계 기준 날짜와 범주 경계는 기술문서/원본에서 확인한다.
- LINK/JSON, 무료, 이용허락범위 제한 없음, 개발 자동승인·운영 심의승인. 관측 기간 공란. 등록 2021년 11월 17일, 메타데이터 수정 2026년 10월 15일.
- 활용: 식사 시간대별 상권 수요 점수, 야간 방문 후보 생성. 카드 이용량을 실시간 대기시간으로 표시하지 않는다. [공식 상세](https://www.data.go.kr/data/15094892/openapi.do)

### H05 관광지 및 상업지구 연령대 성별 카드 데이터

- 수준 B. [허브 606](https://www.jejudatahub.net/data/view/data/606), [교육부 연계 메타데이터](https://data.edmgr.kr/dataView.do?id=jejudatahub-net-606).
- 제목과 API 기술문서 이름을 확인했다. 실제 열, 기간, 집계 공간, 현행 인증 방식은 미확인이다. 연계 포털의 `cc-zero` 표시는 원문 이용조건을 재확인할 필요가 있다.
- 활용: 선택적으로 제공한 연령대에 따른 지역 후보 보정. 사용자 선호를 집계통계만으로 단정하지 않는다. 초기 MVP에는 연령·성별 없이도 동작하게 설계한다.

### H06 제주특별자치도 음식점 목록 통합

- 수준 B. [허브 780](https://www.jejudatahub.net/data/view/data/780), [교육부 연계 메타데이터](https://data.edmgr.kr/dataView.do?id=jejudatahub-net-780).
- 일반·휴게 음식점의 사업장명, 인허가일자, 영업상태, 소재지주소를 제공한다는 설명과 CSV 파일 링크를 확인했다. 원 출처는 LOCALDATA로 표기된다. 관측 기준일은 미확인이다.
- 특히 연계 설명은 좌표 변환 문제로 허브 파일에서 좌표를 제외했다고 명시한다. 따라서 허브 CSV에 위경도가 있다고 가정하지 말고 주소 기반 지오코딩과 좌표 검수를 계획한다. 원본 좌표계는 메타데이터에 오기가 있을 수 있으므로 원본 명세로 확인한다.
- 연계 포털 표기는 `cc-zero`; 원문 파일 이용조건 재확인 필요. 맛·평점·가격·방문자 수·영업시간 제공은 확인되지 않았다. [확인한 설명](https://data.edmgr.kr/dataView.do?id=jejudatahub-net-780)

### H10 일일 정류소별 버스 이용자 정보

### H11 일별 시간대별 버스 승차 인원 수 현황

- 수준 B. [허브 512](https://www.jejudatahub.net/data/view/data/512), [교육부 연계 메타데이터](https://data.edmgr.kr/dataView.do?id=jejudatahub-net-512).
- 일별 이용 시간대별 승차 인원 수라는 설명과 CSV 파일명, 제공처 제주빅데이터센터 표기를 확인했다. 시간대 폭, 지역/정류소 차원, 수록 기간은 미확인이다.
- 허브와 센터를 별개 데이터로 두 번 계산하지 않도록 원 제공기관·원본 데이터 버전·집계 키를 추적한다. 활용: 시간대별 버스 수요 모델의 후보 레이블. 실시간 승차 인원으로 제시하지 않는다.

### H12 일별 기상 정보와 시간대별 외식업 이용자수

- 수준 C. 관련 링크에서 [기상 허브 후보 579](https://www.jejudatahub.net/data/view/data/579), [외식업 허브 후보 490](https://www.jejudatahub.net/data/view/data/490)를 발견했다.

- 기상 특징과 시간대별 식사 수요는 설계상 유용하지만, 확보되었다고 보고하지 않는다. 예측일에 실제로 이용 가능한 예보/과거 관측을 구분해야 하며 미래 관측값으로 과거 수요를 예측하는 누수를 막는다.

| 방문 시간 추천 | H04 H11 | 시간대별 수요 수준 예측 | 혼잡과 대기시간의 직접 관측은 아님 |
| 버스 접근성 | H07 H08 | 정류소 접근 거리와 노선 존재 확인 | 실제 운행 가능 경로에는 시간표·정차 순서 추가 필요 |
| 버스 수요 예측 | H09 H10 H11 | 날짜/노선/정류소별 수요 회귀 | 수요가 높다는 이유만으로 교통수단을 강제하지 않음 |
| 인기 경로 제안 | 인기 지역 점수와 검증된 이동 그래프 | 제한시간 안의 경유지 선택 최적화 | 관측된 실제 대중의 이동 순서와 구별해 표시 |

### 인기 경로를 관측한 것으로 표시하려면 필요한 자료

여러 장소의 월별 방문자 수가 있어도 누가 A 다음 B를 방문했는지 알 수 없다. 실제 인기 방문 순서를 학습하려면 적법하게 제공되는 집계 OD 또는 익명화된 여행별 방문 순서 자료가 필요하다. 확보 전에는 `인기 지역을 연결한 추천 경로`로 표시한다. OD만 있어도 동일인의 하루 전체 여행 시퀀스를 재구성할 수 있다고 가정하지 않는다. 센터의 반출 승인 집계 OD가 확보되면 `전이 확률 기반 경유지 추천`을 별도 실험하고 원본 개인 이동기록을 서비스 DB에 저장하지 않는다.

### 최소 학습 및 검증 절차 제안

1. H01 또는 H03의 관측 월 범위를 확인하고 최소 12개월 이상 연속성이 있는지 검사한다.
2. 최근 기간을 테스트로 남기고 시간 순서대로 학습/검증/테스트를 나눈다. 모든 인기도 평균·전이 확률·결측 보간은 각 학습 구간에서만 계산한다.
3. 전월값과 전년동월값, 이동평균을 기준선으로 두고 Poisson/Tweedie 또는 트리 회귀 모델과 비교한다. 12개월 미만이면 계절성 성능을 주장하지 않는다.
4. 지역 수요에는 MAE/Poisson deviance와 상위 지역 순위 지표를 사용한다. 클릭/방문 정답이 없다면 개인화 정확도를 입증했다고 말하지 않는다.
5. 추천 경로는 방문시간·식사시간·예산·귀환시간·영업시간 제약의 만족률을 별도로 검증한다. 최적화 결과와 ML 예측 성능은 다른 평가다.

## 확보 직후 확인할 항목

- API 인증키 발급과 프로젝트별 이용량: 현재 허브 안내 페이지를 읽지 못했으므로 코드에 추측한 엔드포인트나 임의 data code를 고정하지 않는다.
- 파일/응답 샘플의 실제 열 이름과 자료형, 인코딩, 페이지네이션, 코드북, 결측치/비공개 처리 기호.
- 관측 기간과 최종 관측일, 갱신 이력, 코로나 시기와 이후 시기의 구조 변화.
- 소비 통계의 표본 카드사와 이용자 중복 정의, 업종·지역 합산 가능 여부.
- 지역 코드와 경계의 연도, 주소 변경, 동일 상호/지점 구분, 폐업 및 중복 사업장.
- 원 제공기관, 허브 재배포본, 센터 원자료가 같은 자료인지 확인하고 데이터 계보를 남긴다.
- 라이선스 및 원자료/가공집계/학습모델의 반출·배포 조건을 원본별로 기록한다.

# 제주 길벗 v25 도로 가속과 운영 데이터

## 자동차 지도에서 달라진 점

출발지와 방문지의 좌표를 도로 그래프에 연결할 때 후보 셀을 거리 하한으로 좁힙니다. Windows에서 배정밀도를 지원하는 OpenCL GPU가 있으면 `run_center.cmd --road-gpu`로 선택 가속을 사용할 수 있습니다. 서버를 이미 실행 중이면 종료한 뒤 이 옵션으로 다시 시작합니다. 개발용 명령은 `runtime\python.exe -B dev.py run --road-gpu`입니다. [OpenCL 배정밀도 사양](https://registry.khronos.org/OpenCL/specs/unified/html/OpenCL_C.html#double-precision-floating-point-support)

GPU는 기존과 같은 5×5 후보 셀에서 각 셀의 최근접 후보를 동시에 찾습니다. CPU에서 후보의 실제 거리를 확인하고, 거리 차가 작은 셀은 기존 방식으로 다시 비교합니다. 같은 거리에서는 작은 OSM 노드 ID를 선택하고 연결 허용 거리는 1.5km입니다. 시작점과 복귀점이 같으면 한 요청 안에서 결과를 재사용합니다. GPU 작업 뒤에는 요청의 좌표와 임시 계산 버퍼를 초기화합니다.

기본 실행은 CPU입니다. 선택 가속을 켠 상태에서도 시작·방문 좌표가 속한 셀의 노드 수가 충분한 요청만 GPU 후보로 삼습니다. 첫 밀집 경로는 CPU로 계산하면서 GPU를 별도 스레드에서 준비합니다. 준비 중, 장치 미지원, 사용 중인 큐, OpenCL이 반환한 오류에는 CPU가 대응합니다. 일반 지도 연결 API의 `snap_backend`로 해당 요청의 실행 경로를 확인할 수 있습니다. 일정 선택, 도로 경로 연결 A*, 운영 모델 학습 결과는 기존 방식입니다.

## 속도와 결과 검증

개발 노트북 RTX 3080 Laptop GPU 16GiB에서 로컬 도로 그래프 284,667개 노드를 사용했습니다. 그래프가 메모리에 올라간 뒤 각 경로와 실행 방식에서 12번을 교차 측정했습니다. 표는 중앙값이며 도로 API 내부 계산의 시간입니다. GPU 초기화, 브라우저 표시와 HTTP는 별도입니다.

| 경로 | 기존 CPU | 개선 CPU | GPU 비교 |
| --- | ---: | ---: | ---: |
| 제주공항 · 제주시내 3곳 · 공항 복귀 (9.978km) | 185.9ms | 136.7ms | 128.9ms |
| 제주공항 · 하모해수욕장 (41.597km) | 125.2ms | 112.3ms | 115.0ms |
| 제주공항 · 금능식물원 · 섭지코지 (106.761km) | 647.0ms | 625.8ms | 626.1ms |

시내 왕복의 최근접 노드 계산은 기존 CPU 56.52ms, 개선 CPU 8.54ms, GPU 0.72ms였습니다. 지도 결과 전체의 중앙값은 개선 CPU에서 GPU로 전환할 때 7.8ms 줄었습니다. 이 코스에서 GPU의 95% 지점은 CPU보다 높게 측정됐습니다. GPU 준비는 이 시험에서 1.48초 걸렸습니다. 두 외곽 사례의 GPU 열은 비교용 강제 실행이며 실제 설정에서는 개선 CPU를 사용합니다.

공개 제주공항과 관광지 좌표 및 실제 OSM 노드 569건에서 기존 CPU, 개선 CPU, GPU의 노드 ID와 거리가 모두 일치했습니다. 동점, 1.5km 안팎, 빈 셀을 확인했습니다. 세 실제 코스에서 경로 좌표, 거리, 연결선과 경고가 일치했습니다. 개발 PC에서 밀집 코스의 첫 CPU 처리와 이후 GPU 사용, 외곽 코스의 CPU 선택, 동시 호출 결과를 확인했습니다. 센터 PC에서의 GPU 실행과 응답시간은 탑재 시 확인할 항목입니다.

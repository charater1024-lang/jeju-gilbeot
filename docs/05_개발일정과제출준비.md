# 개발 일정과 대회 제출 준비

2026년 10월 26일부터 11월 20일 오전 10시까지를 기준으로 잡았다. 공식 대회는 기획서 15페이지 이내와 실행 소스 ZIP을 요구한다. 상세 제출 형식은 최종 공지를 다시 확인한다. 심사 세부 배점은 이번 조사에서 확인되지 않아 다른 대회의 배점을 적용하지 않는다.

## 일정과 완료 기준

| 기간 | 작업 | 완료 기준 |
|---|---|---|
| 10월 26~28일 | 데이터 명세·이용 신청·범위 확정 | 두 플랫폼 원본 및 코드북 확보 계획, 권한과 집계 단위 기록 |
| 10월 29일~11월 2일 | 자료 취득·지역코드·주소 정제 | 최소 24개월 지역 집계 가능 여부, 장소 좌표 품질 보고 |
| 11월 3~6일 | 실제 수요 모델과 기준모델 | 시간 분할 결과와 누수 감사, 실제 계절성 학습 가능 판단 |
| 11월 7~11일 | 추천 결합·실제 이동 행렬·UI | 지역 점수 기반 장소 후보, 시간·예산·귀환 검증 |
| 11월 12~15일 | 센터 실행환경 및 사용자 검증 | 비전문가 3~5명 시연, 실패 시나리오와 사용성 개선 |
| 11월 16~18일 | 모델·데이터·매뉴얼 정합성 | 원자료/모델 반출 확인, 재현 실행, 제안서 최종화 |
| 11월 19일 | ZIP 검증과 제출 리허설 | 깨끗한 PC에서 설치·실행, ZIP 누락·키 유출 검사 |
| 11월 20일 10시 이전 | 제출 완료 확인 | 플랫폼 접수 상태·제출 파일 해시 보관 |

일정은 제안이며 자동 예약이나 신청이 아니다. 현재 ZIP은 개발 시작 패키지다. 실제 자료를 활용한 최종 제출물로 바로 내면 안 된다.

## 범위 결정 시점

10월 29일까지 점포별 이용량 확보 가능성이 없으면 식당별 인기 ML을 제출 핵심에서 제외하고 지역 수요 ML을 완성한다. 11월 7일까지 버스 시간표와 경유순서가 없으면 버스 수요 분석만 제공하고 버스 길찾기는 제한한다. OD가 없으면 결과 명칭을 인기 지역 연결 경로로 고정한다.

지역 카드 자료를 하나 이상 실제로 학습하고 원천 설명과 출력까지 연결하는 것이 우선이다. 모델 복잡도·LLM 수·데이터 목록 수보다 실행 재현성과 근거 정확성을 우선한다. 두 플랫폼의 실질 활용은 출처 계보와 실제 입력 특징을 통해 입증한다.

## 역할 분담 제안

1인 개발이라면 데이터·ML을 먼저 만들고 UI와 제출 문서를 뒤에 붙인다. 3~5인 팀이면 데이터/정제, 모델/평가, 경로/교통, UI/사용자 검증, 통합/제출로 나눈다. 각 작업의 출력은 데이터 계약과 버전별 모델로 연결한다. 팀 구성은 대회 최대 인원과 중복 참여 제한을 확인한 뒤 등록한다.

## 자원과 비용

현재 로컬 시제품은 Python 표준 라이브러리만 사용하며 외부 API 요금이 없다. 센터 최소사양 i7-8700, GTX 1060, RAM 32GB에 맞춰 CPU로 동작하는 경량 모델을 우선한다. 실제 같은 사양의 처리시간과 메모리는 아직 측정하지 않았다.

주소 지오코딩, 실제 교통/지도, 선택적 LLM API는 서비스 제공자의 가격·호출한도·이용조건 확인 후 별도 예산을 잡는다. 아직 선택하지 않은 공급자의 무료 한도나 월 비용을 확정값으로 제시하지 않는다. 현재 실행에는 해당 서비스가 필요하지 않다.

## 최종 제출 패키지

- 기획서: 실제 구현 기능과 한계를 반영한 15페이지 이내 자료
- 소스: 실행 코드, 데이터 변환, 모델 학습·추론, 프롬프트 사용 여부
- 모델: 사용 모델·학습 범위·가중치·검증 결과와 버전
- 데이터: 출처·이용조건·원본 ID·기간·측정단위·해시·취득 방법
- 매뉴얼: 설치, 시작·종료, 입력 예시, 오류, 데이터 부족, 외부 의존성
- 환경: Python·라이브러리 버전, .env.example, API Key 제외
- 재현: 실제 테스트 명령, 검증 산출물, 한계와 실패 사례

대회 소유권 조항은 결과물의 센터 소속 및 제공 관련 내용을 포함한다. 이 패키지에는 임의의 오픈소스 라이선스를 부여하지 않았다. 제출 전 공식 규정과 제3자 코드·데이터·모델의 권리를 함께 검토한다.

## 3분 시연 구성

첫 장면에서 데이터 출처와 관측 단위를 보여준다. 다음으로 자연·음식 취향과 예산을 입력해 ML 예측이 포함된 경로를 만든다. 세 번째는 혼잡회피 또는 예산 변경으로 추천이 바뀌는 모습을 보여준다. 마지막으로 버스 자료 부족·불가능 예산의 실패 처리를 보여주고 실제 자료 성능과 한계를 제시한다. 현재 합성 시제품을 시연할 때에는 처음부터 가상 자료임을 명시한다.

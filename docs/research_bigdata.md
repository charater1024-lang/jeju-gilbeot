# 제주빅데이터센터 데이터 조사와 대회 대응

확인일 2026년 10월 26일. 이 문서는 공개 웹에서 확인한 사실과 구현 제안을 구분한다. 원본 파일을 취득하거나 센터 데이터 이용 승인을 받은 상태는 아니다.

## 핵심 판단

제주빅데이터센터는 제주데이터허브와 다른 별도 공개 포털로 취급하기보다, 허브의 센터 메뉴와 센터 제공 공개 데이터 및 방문 분석 데이터를 함께 조사해야 한다. 센터 공식 목록 주소는 [데이터 명세서](https://www.jejudatahub.net/center/data)다. 현재 조사 환경에서 이 주소와 허브 상세 페이지는 웹 방화벽 응답을 반환하여 원본 명세서와 CSV 내용을 확인하지 못했다. 접근 제한 우회는 수행하지 않았다.

교육부와 한국교육학술정보원이 운영하는 [교육데이터 활용 지원 서비스](https://data.edmgr.kr/)의 메타데이터에는 제주빅데이터센터를 제공처로 명시한 외식업·카드·버스 공개 데이터가 있다. 이 목록은 원본 데이터의 존재를 확인하는 보조 근거이며 원본 데이터 취득 증빙을 대신하지 않는다.

### 허브 API와 연결할 수 있는 데이터

[내국인 관광객 지역 업종 성별 연령대별 카드 이용 데이터](https://www.data.go.kr/data/15094857/openapi.do)는 제주특별자치도가 공공데이터포털에 제공한 LINK형 JSON API다. 공개 설명은 월 집계이며 날짜·시도·시군구·읍면동·업종·관광객 구분·연령대·성별·이용자수·이용횟수·이용액을 안내한다. 2026년 10월 15일 수정, 무료, 이용허락범위 제한 없음, 개발 자동승인·운영 심의승인으로 표시되어 있다. 시간범위는 공란이다. 포털의 갱신주기 `실시간` 표기를 관측치가 실시간이라는 뜻으로 해석하면 안 된다. 실제 수록 월과 호출 정책은 API 사용 신청 후 확인한다. 연결된 [허브 상세 597](https://www.jejudatahub.net/data/view/data/597) 및 [교육부 메타데이터](https://data.edmgr.kr/dataView.do?id=jejudatahub-net-597)와 같은 데이터 계열이다.

[일일 노선별 버스 이용자 정보](https://www.jejudatahub.net/data/view/data/614)는 [교육부 메타데이터](https://data.edmgr.kr/dataView.do?id=jejudatahub-net-614)에 API HWP 문서 링크가 있다. 제목상 일·노선 단위인 점만 확인되었다. 실제 응답 필드·수록기간·인증·이용허락은 원문 확인 전 미확정이다.

## 데이터로 말할 수 있는 범위

집계 소비 데이터로는 지역·업종의 이용 빈도와 소비 분포를 설명할 수 있다. 업종·성별 집계를 개별 식당의 고객 수나 품질 점수로 표시하면 근거가 잘못된다. 특정 식당의 실측 인기 순위를 제공하려면 사업체 식별자 또는 상호·주소와 연결되는 점포 단위 이용량 자료가 필요하다.

이용자 수와 이용 건수는 다르다. 카드·POS·와이파이 사용자 수는 각 제공기관의 관측 범위 안에서 집계된 수이며 제주 전체 방문객 전수와 동일하지 않다. 카드 금액은 인기 외에 객단가 영향을 받으므로 원금액만으로 맛집을 순위화하지 않는다.

정류소별 이용자 수나 노선 이용량은 실제 승객 이동 순서를 나타내지 않는다. 버스 수요의 인기도와 실제 운행 가능성도 다르다. 방문 순서를 학습하려면 익명화된 이동 OD 또는 연속 방문 시퀀스가 필요하다. 이를 받기 전 경로는 사용자가 선호할 장소를 고른 후 거리·시간 제약으로 계산한 추천 경로라고 표시한다.

버스 시간표·운행일·노선 정류소 순서·환승·도보 연결은 이용량 집계와 별도의 데이터다. 현재 버스 수요 CSV만으로 정확한 도착시각이나 환승시간을 보장할 수 없다. 시간표를 확보하기 전에는 대중교통 경로의 정밀 시각 출력을 제한한다.

## 센터 활용과 자료 이용 계획

정부 [기업마당의 2026년 센터 운영사업 공고](https://www.bizinfo.go.kr/sii/siia/selectSIIA200Detail.do?pblancId=PBLN_000000000123093)는 제주테크노파크가 데이터 분석 및 활용 컨설팅을 수행한다고 안내한다. [제주테크노파크 원문](https://www.jejutp.or.kr/board/business/detail/38a3272fcbb846c7ab3161038f390b99?cate=&keyword=&pageNumber=0)과 연결된다. 이는 센터 지원 창구의 존재에 대한 근거이며 개별 데이터 반출 허락을 의미하지 않는다.

최우선 요청 명세는 다음과 같다. 이는 센터 보유가 확인된 개별 상품명 목록이 아니라 확보를 위한 요구사항이다.

| 확보 요청 대상 | 최소 필요 항목 | 확보 시 구현할 기능 | 미확보 시 동작 |
| --- | --- | --- | --- |
| 점포 단위 익명 집계 POS 또는 소비 | 점포키, 지역 또는 좌표, 집계월, 업종, 건수, 이용자수, 집계 기준 | 데이터 기반 식당 인기도 예측 | 지역·음식 유형 선호만 사용하고 식당 실측 인기 배지 숨김 |
| 관광지역 유동인구 | 지역키, 일자 또는 월, 시간대, 관측량, 표본/보정 기준 | 혼잡 시간대 예측 | 과거 이용량 참고 표시만 제공 |
| 이동 OD 또는 연속 방문 집계 | 출발/도착 지역키, 관측기간, 이동 건수, 익명화 조건 | 지역 간 방문 전이 모델 | 지리·시간 제약으로 경로 구성 |
| 노선별 승하차 집계 | 노선키, 정류소키, 날짜, 시간대, 승하차량 | 버스 이용 패턴/혼잡 보조 예측 | 통계 없는 운행 가능성 검증만 수행 |
| 이용권한 및 반출기준 | 목적, 외부 제출 가능 산출물, 모델 반출 허용, 보존기간 | 제출 패키지와 재현 계획 확정 | 승인된 공개 데이터만 포함 |

각 데이터에 출처, 원본 URL, 데이터 소유·제공기관, 취득일, 수록기간, 관측단위, 라이선스 원문, 파일 SHA256, 허브/센터 관계, 전처리 버전, 모델 입력 특징을 기록한다. 센터 내부 분석 자료를 허브 공개 데이터와 중복 수집한 경우 독립 데이터셋 두 종으로 성과를 부풀리지 않는다. 원자료와 모델의 반출 가능성은 각각 확인한다.

## 권장 구현 우선순위

이하 내용은 조사 사실이 아닌 설계 제안이다. 운영 PC에서 CPU 추론 가능한 표 기반 모델을 우선한다. 첫째 공개 데이터의 날짜·지역·업종 단위를 맞춰 소비와 방문 수요를 예측한다. 둘째 사용자 선호와 예측치를 결합해 후보 장소를 선별한다. 셋째 이동 행렬과 영업·예산 제약으로 실행 가능한 순서를 구한다. 넷째 통합 Agent가 데이터 부족·실패·불가능 조건을 감지해 후보 범위나 요청 조건을 조정하고 근거와 함께 결과를 반환한다.

성능 검증은 시간순 분할과 당시 이용 가능 데이터만 사용하는 특징 생성으로 수행한다. 미래 소비량이 섞인 같은 달 집계를 학습·검증 양쪽에 쓰지 않는다. 실제 수요 예측은 MAE/WAPE와 계절 평균 기준모델을 비교하고, 여행 추천은 사람이 작성한 시나리오에서 시간·예산 위반률과 근거 정확도를 측정한다. 실데이터 취득 이전 합성 자료로 얻은 수치는 모델 성능 증거로 제출하지 않는다.

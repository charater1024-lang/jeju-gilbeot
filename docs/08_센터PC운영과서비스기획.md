# 제주 길벗 센터 PC 운영과 서비스 기획

버전 3 기준일 2026년 10월 27일. 제주빅데이터센터를 방문한 도민과 관광객이 센터 PC에서 직접 장소를 탐색하고 과거 소비·이동 패턴을 참고해 하루 일정을 만드는 서비스를 다룬다. 우선 배포 대상은 센터 방문자용 로컬 PC다. 외부 이용자가 접속하는 웹 서비스는 별도의 확장 단계로 구분한다.

이 문서와 `09_실데이터모델검증.md`는 버전 3의 운영과 현재 모델 선택을 설명한다. 기존 기획서와 07번까지의 문서에는 이전 버전의 구현·실험 기록이 포함되어 있다.

## 방문자가 사용하는 핵심 흐름

첫 화면에서 실제 제주 관광지 사진과 공식 참조정보를 살펴보고 마음에 드는 장소를 담는다. 음식점 영역에서는 관광객 또는 도민을 선택하여 해당 집단의 과거 식음료 업종 구성비와 업종에 연결한 음식점 명부를 확인한다. 이동 시간대 비교에서는 선택한 날짜의 요일에 대응하는 과거 일반 승차 패턴을 시간당 기준으로 비교한다. 저장한 장소의 방문 순서는 사용자가 정한 시간·이동수단·추정 이동비 조건에 맞춰 구성한다.

결과에서 장소·순서·도착과 출발 시간·출처·추정 이동비·미확인 비용을 확인하고 자체 포함 HTML 일정 파일로 저장할 수 있다. 파일은 사진과 외부 실행 코드 없이 열 수 있다. 실제 운영·예약·입장료·도로와 운행시간은 출발 전에 확인해야 한다.

## 센터 운영 환경

| 구분 | 현재 설계와 적용 범위 |
| --- | --- |
| 기준 PC | Intel Core i7 8700 및 RAM 32GB 사양을 운영 목표로 삼음 |
| GPU | GTX 1060이 있는 기준 환경을 고려하되 현재 추론과 검색에서 GPU를 사용하지 않음 |
| 실행 방식 | Python 로컬 HTTP 서버와 브라우저를 같은 PC에서 실행 |
| 접속 주소 | http://127.0.0.1:8765 |
| 네트워크 | 핵심 탐색·모델 조회·일정 생성은 오프라인 실행 설계 |
| 외부 API | 핵심 서비스 요청에서 필요한 외부 API 호출 0개 |
| 자료 저장 | 로컬 JSON 모델과 읽기 전용 SQLite 검색 색인 |
| 개인정보 입력 | 계정·성별 입력 없이 도민 또는 관광객 참고 모드를 직접 선택 |
| 방문자 목록 | 브라우저 sessionStorage에 현재 탭의 장소 목록 보관 |

사진·CSS·JavaScript는 프로젝트에 포함된 로컬 파일을 사용한다. 출처 링크는 외부 공식 웹페이지로 연결되므로 오프라인에서는 열리지 않을 수 있다. 링크를 열지 않아도 기본 탐색·모델 조회·일정 초안과 파일 저장을 사용할 수 있다. 데이터 재취득은 관리자 갱신 작업으로 분리한다.

센터 PC에서의 실제 설치 성공률·응답시간·브라우저 포함 메모리 사용량은 현장 검증 항목이다. 개발 호스트의 함수 호출 벤치마크를 센터의 i7 8700 장비에서 측정한 결과로 표시하지 않는다. 공식 Windows x64 휴대용 런타임의 출처·SHA256·서명·라이선스 검증은 `docs/runtime/source_report.json`에 보존했다. 현재 개발 PC에서 실행했으며 깨끗한 센터 PC의 현장 검증은 남아 있다.

## 자료와 화면에서 제공하는 범위

| 기능 | 현재 연결한 자료 | 방문자가 확인하는 정보 |
| --- | --- | --- |

| 음식점 검색 | 원본 인허가 51,111행에서 과거 영업·정상으로 기록된 20,954행 | 이름·주소·자료상 업종과 상태·원문 출처 |
| 집단 식음료 경향 | 센터 카드 자료 1048의 90개월·2집단·8업종 | 8개 업종 안에서 학습한 과거 이용건수 구성비 |

| 주차장 위치 참고 | 여행장소 이름에 주차가 포함된 참조 위치 6곳 | 이름·주소·출처, 운영·요금·잔여면수 미확인 표시 |

추가 장소 색인은 원본 5,669행에서 일반적인 일정 메모 128행, 주소·좌표 결측이나 검수 범위 밖 77행, 동일 이름·주소·좌표 기준 중복 83행을 제외하여 5,381행이 되었다. 일정 메모 필터는 `1일차`, `점심`, `숙소`, `렌터카 반납` 등의 일반 표현을 대상으로 하는 규칙이다. 이 정리가 모든 장소의 실재 여부와 현재 운영, 정확한 입구를 현장 검수했다는 뜻은 아니다. 좌표 범위 검수는 제주 본섬 주변을 대상으로 하므로 외곽 섬의 일부 기록은 검색 색인에서 빠질 수 있다.

여행장소 자료의 최종 행 수정일은 2025년 9월 18일이고 음식점 자료의 최종 행 갱신일은 2025년 9월 2일이다. 각 목록의 모든 행이 해당 날짜에 확인되었다거나 현재도 운영 중이라고 해석하지 않는다. 주차장 6곳도 전체 공영주차장 목록이 아니다.

## 도민과 관광객 모드

도민은 원자료의 `제주도민`, 관광객은 원자료의 `내국인` 분류를 참고한다. 원자료에는 법인·중국·일본·동남아·기타외국 구간도 있지만 현재 화면의 두 집단에 임의로 합치지 않는다. 관광객 모드가 모든 국내외 관광객을 대표하는 것은 아니다. 이용자의 실제 거주지나 개인 선호를 추론하는 기능도 아니다.

카드 원자료의 남성·여성·알수없음 행에서 관측 이용건수인 `use_count`를 합한 뒤, 월별로 선택한 8개 식음료 업종 안의 구성비를 만든다. 현재 서비스는 검증 기준에 따라 월별 구성비의 집단 평균 모형을 선택했다. 따라서 월 선택이 출력을 바꾸는 것처럼 보이지 않도록 월 선택을 숨기며 집단 평균 경향을 사용한다는 안내를 제공한다.

식당 예시는 집단별 업종 경향과 명부의 업종을 연결하고 서로 다른 업종도 함께 보이도록 구성한다. 각 업종 안에서는 이름순 예시를 사용한다. 개별 음식점의 방문객 수·맛 평점·개인 취향 정확도나 인기 순위로 표시하지 않는다. 카드 자료에 점포 좌표와 개별 식당의 방문량이 있는 것처럼 결합하지 않는다.

## 이동 시간대 비교

512의 `일반`은 승차권 유형이다. 도민·관광객 구분이 아니므로 두 모드에서 서로 다른 거주집단의 버스 수요를 보여주지 않는다. 기본 분석은 완전 관측된 일반 유형의 4,704행을 사용한다. 다른 유형의 희소 셀을 0으로 채우지 않는다.

01시부터 06시 구간은 6시간이고 다른 6개 구간은 각각 3시간이다. 막대는 총인원이 아니라 구간의 관측 인원을 구간 길이로 나눈 시간당 지표를 비교한다. 현재 서비스는 검증에서 Ridge 후보보다 오차가 낮았던 과거 요일·시간구간 평균을 사용한다. 날짜 선택은 과거의 해당 요일 패턴을 조회하기 위한 조건이며 그날의 실시간 혼잡을 예측했다는 뜻이 아니다.

자료의 마지막 관측일은 2025년 10월 26일이다. 화면에는 관측기간과 현재보다 오래된 자료임을 표시한다. 특정 노선·정류소의 혼잡, 차량 좌석·잔여 좌석, 실제 출발·환승·도착 시간이나 운행 여부를 제공하지 않는다. 승차 집계를 확보했다는 이유만으로 버스 경로 생성 제한을 해제하지 않는다.

## 장소 저장과 센터 공용 PC 초기화

현재 탭에서는 대표 관광지와 추가 검색 장소를 합해 최대 8곳까지 저장한다. sessionStorage에는 저장 ID와 검증한 추가 장소의 최소 참조정보만 보관하고, 최대 항목 수와 직렬화 크기 64KB를 제한한다. 추가 장소는 `featured:false`로 구분하여 대표 실사진 갤러리 10곳에 섞이지 않도록 한다. 이전 버전의 localStorage 목록은 읽지 않는다.

방문자가 체험을 마치면 머리글의 새 여행 시작을 누른다. 이 버튼은 저장 목록·추가 장소·검색어·지역·집단 선택·날짜와 폼·생성한 일정·상세 화면을 초기 상태로 되돌린다. 이전 요청의 늦은 응답이 초기화 뒤 결과를 되살리지 않도록 요청 순서를 검사한다. 자동 시간제 초기화는 이번 버전에 넣지 않았다. 관리자는 다음 방문자에게 PC를 넘기기 전에 새 여행 시작 또는 체험 탭 닫기를 수행한다.

다운로드한 HTML 일정 파일은 사용자가 따로 저장한 결과물이므로 브라우저 목록 초기화와 함께 삭제되지 않는다. 공용 PC의 다운로드 폴더 정리는 센터의 파일 보관 정책에 맞춰 별도로 운영한다. 이 애플리케이션이 다른 개인 파일을 자동 삭제하도록 구성하지 않는다.

## 경로 탐색과 모델의 역할 구분

SQLite는 장소와 음식점의 정적 검색 색인이다. 대표 관광지와 추가 장소는 ID로 조회하고 화면의 임의 좌표를 그대로 신뢰해 경로에 삽입하지 않는다. 현재 실제 장소의 순서는 선택한 장소를 모두 포함하는 순서를 비교해 시간과 추정 이동비 제약을 검사하는 규칙 기반 탐색이다. 집단 소비 모형이나 승차 패턴 모형이 장소의 방문 순서를 직접 학습한 것은 아니다.

입장료·식사비·주차비·대여료·실제 도로망·영업·휴무·예약은 별도 확인 대상이다. 전체 예산을 충족하거나 실제 도로를 통과할 수 있다고 보장하지 않는다. 섬 이동은 배편, 한라산은 실제 탐방로 입구와 예약, 버스는 시간표가 필요하므로 근거가 없는 조건에서는 계산을 제한한다. 별도로 선택하는 합성 ML 추천 체험에는 가상 장소·합성 방문량 표시를 유지한다.

통합 Agent는 요청 해석·집계 분석·음식점 후보 연결·이동 조건 검토·경로 탐색·근거 안내 도구를 로컬에서 조정하는 실행 흐름이다. 여러 역할 이름과 실행 이력을 반환하지만 현재 실행 방식은 `local_tool_pipeline`이다. LLM이 임의로 도구를 선택하고 외부 사이트를 돌아다니거나 코드를 생성·실행하는 자율형 다중 Agent로 설명하지 않는다. 데이터 교체와 학습·배포는 관리자가 수행한다.

## 설치와 운영 절차

포터블 패키지는 `run_center.cmd`를 더블클릭하여 서버와 브라우저를 시작한다. 공식 Python 3.13.17 x64 런타임을 포함하여 Python/pip의 별도 설치가 필요 없다. 휴대용 런타임으로 실제 추론과 HTTP 요청 16개를 현재 개발 PC에서 검증했다. 센터의 OS·UCRT·보안정책과 깨끗한 PC에서의 설치 성공률·실행 시간은 현장 확인 항목이다.

소스 기준 실행은 Python 3.10 이상에서 프로젝트 폴더를 열어 다음 명령을 사용한다. 현재 런타임의 핵심 서비스에는 별도 pip 패키지와 API Key가 필요하지 않다.

```powershell
python -m jeju_agent serve --open-browser
```

브라우저에서 로컬 주소가 열리면 대표 관광지, 음식점 집단 경향, 시간대 비교, 추가 장소 검색이 정상 응답하는지 확인한다. 한두 장소로 실제 일정 초안을 만들고 파일 저장과 새 여행 시작을 확인한다. 종료는 서버를 실행한 터미널에서 Ctrl+C로 수행한다. 포터블 배포본도 같은 방식으로 종료한다. 다운로드한 HTML 파일은 브라우저 세션 초기화와 별개로 다운로드 폴더에 남으므로 운영자가 관리한다.

검색 색인과 학습 모델을 갱신하는 명령은 방문자가 실행하는 기능과 분리한다.

```powershell
python scripts/build_catalog.py
python scripts/train_audience.py
python scripts/train_mobility.py
python -m unittest discover -s tests -v
```

원자료를 바꿀 때는 파일 출처·해시·열·관측기간과 데이터 이용범위를 확인하고, 모델과 검색 색인·프로파일·검증 수치를 함께 갱신한다. 약 498MB의 별도 버스 원자료는 서비스 요청이나 추론 때 로드하지 않는다. 실행 패키지의 원자료 포함 여부와 대회 제출·재배포 범위는 별도로 관리한다.

## 향후 웹 서비스 확장

센터 PC 운영에서 사용성·자료 갱신·현장 응답·세션 초기화를 먼저 검증한다. 향후 외부 웹 서비스로 확장할 때는 외부 접속을 위한 배포 구조와 동시 이용, 서버 저장 정책, 데이터 갱신, 실제 지도·운행·가격 자료와 장애 대응을 새로 설계한다. 현재의 loopback 로컬 서버를 그대로 인터넷 서비스라고 제공하지 않는다.

개인화는 사용자 피드백이나 적법하게 이용 가능한 방문·선택 이력이 확보된 뒤 별도로 학습·검증할 과제다. 현재 과거 집단 구성비의 성능을 개인 여행 만족도나 개별 맛집 추천 정확도의 성과로 옮겨 적지 않는다.

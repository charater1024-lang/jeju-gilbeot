# 제주 여행 추천 데이터 활용 설계

기준일 2026년 10월 26일. 원본 취득 상태는 모두 미확보다. A는 제주특별자치도의 공공데이터포털 설명 직접 확인, B는 교육부 공식 연계 메타데이터 확인, C는 추가 조사 후보를 뜻한다. 상세 근거는 조사 파일에 남겼다.

## 두 플랫폼을 활용하는 방식

제주데이터허브는 공개 데이터의 탐색·배포 창구로, 제주빅데이터센터는 심화 분석 자료의 제공·분석 협력 창구로 활용한다. 센터 제공 자료가 허브에서도 배포된다. 같은 자료를 두 번 내려받아 독립 데이터 두 종으로 세지 않는다. `original_dataset_id`, `provider`, `distribution_url`, `version`, `sha256`으로 계보를 관리한다.

많은 자료를 단순 나열하기보다 실제 기능과 모델 입력에 연결한다. 1차 목표는 장소 기준정보, 카드 소비, 버스 기준정보와 수요를 연결한 4개 데이터 계열이다. 센터의 점포별 집계와 OD가 확보되면 별도 모델로 확장한다.

| ID | 데이터명과 원천 | 수준 | 관측 단위와 활용 | 제한 |
|---|---|---|---|---|
| H01 | 내국인 관광객 지역 업종 성별 연령대별 카드 이용 597 | A | 월별 지역 업종 소비 수요 모델 | 개별 점포 방문량 아님 |
| H02 | 관광지 및 상업지구 이용자 유형별 카드 604 | A | 관광객·도민 상권 맥락 | 개인별 유형 추론 금지 |
| H03 | 관광지 및 상업지구 업종별 카드 605 | A | 식음료·교통·문화 수요 | 같은 결제 중복 합산 점검 |
| H04 | 관광지 및 상업지구 시간대별 카드 607 | A | 점심·저녁 등 범주별 수요 | 시간별 실시간 혼잡 아님 |

| H06 | 버스 노선 기본정보 611 | A | 노선 식별과 수요 결합 | 시간표와 정차 순서 별도 |
| H07 | 버스 정류소 기본정보 612 | B | 접근 위치와 정류소 연결 | 보행 경로는 별도 |

| H09 | 일일 정류소별 버스 이용자 613 | B | 정류소별 수요 보조 | 관광객 전용 관측 아님 |

H01 공식 설명에는 월별 소비 집계가 명시되어 있다. API 메타데이터의 수정일이나 업데이트 주기에서 실제 관측 최신일을 추정하지 않는다. 공공데이터포털의 LINK 유형은 이 페이지가 실제 호출 엔드포인트가 아니라는 의미다. API URL·페이지네이션·인증키 이름은 기술문서를 읽은 뒤 구현한다.

## 수집과 전처리

1. 승인된 CSV·API 기술문서를 확보하고 파일 해시와 수집 시각을 저장한다. 원본은 변경 없이 보존하고 가공 산출물과 분리한다.
2. 실제 열 이름, 지역·업종 코드, 통계 측정값, 익명화 표시, 집계 기간, 표본 카드사의 범위를 확인한다. `*`, `-`, 빈값을 무조건 0으로 바꾸지 않는다.
3. 음식점은 상호 문자열보다 인허가 식별자와 주소를 우선해 지점을 구분한다. 폐업·중복·좌표 없는 행을 별도 분류한다. 허브 780은 좌표 제외 설명이 있어 주소 지오코딩과 제주 범위 검수가 필요하다.
4. 지역 집계는 같은 연도의 읍면동 경계와 코드로 결합한다. 버스 정류소·노선은 각각 ID로 결합한다. 이름 유사도만으로 자동 확정하지 않는다.
5. 서로 다른 집계의 총 이용자 수는 중복 이용자가 있을 수 있다. 제공기관의 합산 가능 정의 없이는 지역 합계·성별 합계·관광객 합계를 동시에 더하지 않는다.
6. 최신 데이터의 공개 지연을 반영해 `observed_at`, `available_at`을 분리한다. 예측 시점에 아직 공개되지 않은 월집계를 특징으로 사용하지 않는다.

## 표준 저장 계층

| 계층 | 핵심 테이블 | 주요 키 |
|---|---|---|
| 원본 | raw_file, raw_api_page | dataset_version, sha256 |
| 기준정보 | poi, region, bus_stop, bus_route | poi_id, region_code, stop_id, route_id |
| 관측 | region_demand, stop_demand, merchant_demand | 시간과 해당 공간키와 측정값 |
| 학습 | feature_snapshot, fold, model_version | as_of_date, feature_version |
| 제공 | recommendation, evidence, execution_trace | request_id, plan_id, source_id |

운영형은 SQLite 또는 DuckDB로 시작하고, 공간 검색이 많아지면 PostgreSQL/PostGIS로 전환한다. 현재 시제품은 UTF-8 CSV와 JSON만 사용한다.

## 현재 코드의 데이터 계약

`pois.csv`는 POI 식별자, 명칭, 업종, 지역, 위경도, 태그, 실내 여부, 체류분, 비용, 개폐점 시각, 출처를 요구한다. 실제 음식점 원천에 없는 비용·시간을 임의로 관측값으로 채우지 않는다. 별도 확인 출처와 불확실성 필드를 운영형에 추가한다. 현재 합성 시제품의 수치는 전부 가정값이다.

`demand.csv`는 `date,poi_id,visits,source_id`의 장소별 일별 방문량이다. 같은 일자와 장소는 한 행이어야 한다. 실제 점포 레이블을 확보하기 전에는 사용하지 않는다.

`region_demand.csv`는 `month,region,category,value,measure,source_id`다. `measure`는 이용 건수 transactions, 이용자 users, 금액 amount_krw 중 하나이며 한 모델에서 혼합하지 않는다. 날짜를 일별로 복제해 표본 수를 늘리지 않는다. 성별·연령·관광객 차원을 합칠 때 합산 가능한 건수인지 코드북으로 검증한다. 이용자 수는 중복 제거 정의가 불명확하면 합치지 않는다.

## 데이터 확보 요청서 초안

센터에 요청할 항목은 최소 24개월의 지역·업종별 월별 소비, 점포키가 포함된 익명 집계의 제공 가능성, 버스 노선·정류소·시간대 수요, 집계 OD 제공 가능성이다. 해당 자료를 센터가 실제 보유하고 있다는 확정 목록이 아니라 필요한 분석 명세다. 요청에 연구목적·집계 최소단위·개인정보 제외·원자료 반출·가공집계 반출·학습모델 반출·대회 제출·센터 탑재·보존기간을 각각 적는다.

원자료 미반출이어도 센터 내부에서 학습하고 허용된 모델과 검증 집계만 반출할 수 있는지 확인한다. 승인이 늦어지면 허브 공개 자료로 지역 수요 기능을 완성하고 점포 인기와 OD 기능을 제출 설명에서 제외한다.

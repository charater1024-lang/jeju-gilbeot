01 제안 개요


제주 길벗 여행 데이터
활용 서비스 제안서

제주 AI 빅데이터 활용 AI Agent 개발 챌린지

개인 제안  |  구현 기준 v15  |  2026년 11월 1일

제주 길벗은 센터 방문자가 출처를 확인하며 실제 장소를 찾고, 출발지와 시간에 맞는 관광 코스를 구성하는 서비스입니다. 현재 시제품에는 자동 코스와 직접 고른 장소의 일정 구성을 구현했습니다. 제안자는 자료의 신뢰성과 이용 편의를 검수해 센터에서 직접 실행할 수 있는 결과물로 제출하고자 합니다.

| 제안의 근거 | 현재 확보한 내용 |
| --- | --- |
| 이용자가 받는 결과 | 실제 장소 검색, 근거를 갖춘 자동 코스, 장소 제외 후 재추천, HTML 일정과 출처 저장 |
| 구현 기반 | 관광 후보 68개 중 자동 선별 기준 충족 40개, 공식 소개 62개. 출발지 확인과 중앙 Agent 구현 |
| 모델 검증 | 소비 비중 오차 ±1퍼센트포인트 이내 87.5%, 승차 관측값 대비 오차 ±20% 이내 82.5%. 비교조건은 5~6쪽에 명시 |
| 운영 형태 | 내장 Python을 포함한 로컬 웹앱. 핵심 기능은 유료 LLM 호출과 GPU 없이 실행 |

제출 범위와 제안자의 책임

제안자는 데이터 처리, 모델 학습, 화면 개발과 실행 문서 작성을 직접 수행합니다. 앞으로 실제 입구와 운영시간 확인, 추천 품질 평가와 센터 PC 시연을 우선 진행하겠습니다. 자동 선별 기준 충족은 현재 영업이나 안전한 방문의 보증이 아닙니다. 실시간 교통과 인기 경로 학습은 후속 과제로 관리합니다.

근거 [1] 대회 공고, [2] v15 구현 및 검증, [5] 쉬운 성능지표. 제안 주체는 개인 개발자입니다.

02 이용자와 서비스 이용 흐름


센터를 방문한 도민과 관광객은 원자료의 열 구조나 분석 코드를 익히지 않고도, 관심 있는 지역과 장소를 찾아볼 수 있어야 합니다. 제주 길벗은 출발지를 확인하고 자동으로 코스를 받거나, 검색한 장소를 직접 일정에 담도록 구성했습니다.

화면 설명에서 지킬 기준

관광 소개와 지도·명부의 근거를 구분해 보여줍니다. 자동 코스는 출처·접근 조건을 통과한 관광 후보만 사용하며 음식점 자동 편입은 제공하지 않습니다. 이용자는 원하지 않는 장소를 제외해 다시 추천받고, 장소별 출처와 확인일을 함께 저장할 수 있습니다.

GPS 또는 수동 탐색 위치는 이용자가 일정 출발지로 적용한 뒤 확인합니다. 공항 기본값도 확인이 필요합니다. 복귀지는 출발지와 연결되며, 비공개 위치 좌표는 HTML 저장에서 제외합니다. 근거 [2].

03 현재 제공 기능과 제출 범위


검색·분석·출발지 확인·자동 코스·일정 저장은 현재 시제품에 구현했습니다. 구현 검증과 현장 검증을 구분해 관리하며, 제출 전에는 실제 방문에 필요한 정보와 추천 품질을 보완하겠습니다.

| 구분 | 기능 | 현재 상태와 제출 기준 |
| --- | --- | --- |
| 구현 완료 | 관광·음식 검색과 지도 | 관광 교차확인과 출처 표시, 음식 TF-IDF 검색, 지도 묶음 전체 목록 제공 |
| 구현 완료 | 소비·승차 분석 | 실제 자료로 개선한 두 모델이 화면과 API에 연결됨 |
| 구현 완료 | 상담과 수동 일정 | 규칙과 준비된 안내문, 선택 장소의 시간·이동비 조건 탐색, HTML 저장 |
| 구현 완료 | 일정 출발 기준 | GPS·수동 기준 위치의 명시적 적용·확인, 복귀지 연결, 위치 변경 시 기존 일정 무효화 |
| 구현 완료 | 중앙 Agent와 자동 코스 | 68후보 중 정책 충족 40개에서 조건에 맞는 최대 8곳 선택, 장소 제외 후 재추천 |
| 후속 검토 | 인기 경로와 실시간 교통 | 학습 정답·API 권한·제주 커버리지가 확인된 뒤 별도 추진 |

일정 결과의 의미

자동 코스는 제한된 후보에서 방문 가능한 장소 수를 우선하고, 이어 추정 이동시간과 비용을 비교합니다. 직접 담은 장소는 방문 순서를 비교합니다. 이동시간·이동비는 추정값이며, OSM 선은 참고 경로입니다. 현재 영업시간, 입장료·식사비와 실제 도로의 통행 가능성을 보증하지 않습니다.

한 사람이 완성할 수 있는 범위

자동 선별 자료의 출처가 손상되거나 필수 검수 정보가 없으면 추천을 중단하도록 구성했습니다. 새 자료는 검수 후 반영하고, 실제 입구·운영 정보와 검색·코스 품질을 차례로 확인하겠습니다. 지원하지 않는 조건은 이유와 조정 방법을 안내하며, 인기나 개인 취향을 학습한 추천으로 표현하지 않습니다.

서비스에서 가상 장소와 합성 데이터 기능을 제거했습니다. 과거 개발 이력은 실행 결과와 실자료 성능에서 제외합니다. 근거 [2].

04 데이터 활용과 장소 확인


주요 분석자료는 제주빅데이터센터가 제공하고 제주데이터허브가 배포하는 소비·승차 자료입니다. 장소 명부와 지도는 관광 후보를 연결하는 근거로 사용합니다. 같은 원천자료가 두 플랫폼에 있는 경우에는 독립 자료로 중복 집계하지 않습니다.

관광 후보를 채택하는 절차

이름을 같은 규칙으로 정리한 뒤 정확히 일치하는 기록을 찾고, 두 좌표가 250m 이내인지 확인합니다. 음식·숙박·상점·일반시설을 제외한 다음 근접 중복을 정리합니다. 남은 68개는 이 규칙을 통과한 후보이며 공식 지정 관광지 수가 아닙니다. 자동 코스에는 출처 무결성, 공식 소개·확인일, 배편·접근 제외와 장소별 예외 10건을 추가 적용해 40개를 사용합니다. 현재 운영을 확인한 수치가 아니며 원래 지도 이름도 보존합니다.

갱신과 이용조건 관리

원본, 출처 URL, 관측기간과 파일 해시를 보존하고 가공·학습 이력을 연결했습니다. 자동 선별은 소개 기록과 수집 증빙의 해시를 대조하고 내부 재검토 기한을 180일로 두었습니다. 11월 1일 재조회한 소비·승차 공개 CSV는 보관 원본과 같은 파일입니다. 음식 27,056개는 출처 기록의 합계이며 고유 맛집 수가 아닙니다. 원자료 재배포 조건이 미확인인 항목은 제출 전 확인하고, 확인된 범위로 패키지를 구성하겠습니다.

허브512의 설명 기간과 CSV의 실제 행 기간이 달라 위 표에는 실제 학습에 쓴 날짜를 기재했습니다. 근거 [3] 원본 명세, [4] 현재 파일 확인. OSM은 OpenStreetMap contributors 및 ODbL 조건을 유지합니다.

05 소비 경향 모델의 검증 결과


소비 모델은 도민과 내국인 참고 집단에서 어떤 식음료 업종의 이용 비중이 높은지 보여줍니다. 최근 12개월에 더 큰 가중치를 주고 월별 변화를 학습하는 회귀 모델을 적용했습니다. 출력은 업종 구성비이며 개별 음식점의 맛이나 인기 점수가 아닙니다.

그림 2 소비 비중 추정의 허용오차 내 비율 비교 2024년 1월부터 2025년 6월의 288개 업종 셀

![그림 2 소비 비중 추정의 허용오차 내 비율 비교 2024년 1월부터 2025년 6월의 288개 업종 셀](../../development_support/proposal_v15_20261101/figures/소비허용오차비교.png)

| 비중 오차 1퍼센트포인트 이내 | 158/288  54.9% | 252/288  87.5% |

예를 들어 실제 비중이 20%일 때 19~21%로 추정하면 첫 번째 기준을 충족합니다. 개선 모델은 288개 월·집단·업종 셀 가운데 252개에서 이 범위에 들어왔습니다. 같은 월의 업종 값은 서로 연관돼 있으므로 288명의 독립된 이용자를 시험한 결과로 해석하지 않습니다.

기존 집단별 평균 대비 MAE는 73.26% 줄었습니다. 같은 최근 가중 평균의 허용오차 내 비율도 86.8%로, 개선의 대부분은 최근 분포 반영 효과입니다. 업종별로는 한식 44.4%, 음료점 58.3%가 1퍼센트포인트 기준에 들어와 추가 검토가 필요합니다.

설명용 허용오차를 고정해 계산했으며 현장 합격기준으로 승인된 값은 아닙니다. 모든 비교모형을 같은72개월에 적합했습니다. 기존 과거 테스트 기간을 재사용한 후향 평가입니다. 근거 [5], [6].

06 승차 시간대 모델의 검증 결과


승차 모델은 날짜의 요일과 시간대, 계절적 차이를 반영해 제주 전체의 일반 승차 패턴을 비교합니다. 최근 자료에 가중치를 주고 큰 편차의 영향을 완화하는 Huber 회귀를 사용했습니다. 실제 노선의 혼잡도나 버스 출발시각을 예측하는 기능은 제공하지 않습니다.

그림 3 승차 관측값 대비 오차 20퍼센트 이내 비율 비교 2025년 6월 28일부터 10월 26일의 847개 시간구간

| --- | --- | --- |
| 관측값 대비 오차 20% 이내 | 683/847  80.6% | 699/847  82.5% |

실제 시간당 인원이 1,000명일 때 800~1,200명으로 추정하면 20% 기준을 충족합니다. 이번 평가에서는 847개 관측 중 699개가 이 범위에 들어왔습니다. 시간구간별 인원 차이가 크므로 전체 비율과 시간대별 오차를 함께 확인해야 합니다.

평균 절대오차는 6.44% 줄었습니다. 다만 16~18시와 19~21시의 허용오차 내 비율은 소폭 하락했고, 검증 RMSE도 177.67에서 179.28명/시간으로 증가했습니다. 개선되지 않은 구간을 함께 관리하고 새 자료로 다시 검증하겠습니다.

신규·기준모형 모두 동일한 최초430일로 학습해 같은121일을 평가했습니다. 허용오차 비율은 분류 Accuracy나 신뢰확률이 아닙니다. 근거 [5], [6].

07 Agent 구성과 실행 방식


자동 코스는 중앙 run_agent가 확인된 요청에서 검색, 출처 검사, 장소 선택, 시간·복귀 검증과 설명까지 연결합니다. 생성형 AI의 자유 답변에 사실관계를 맡기지 않고 실제 자료와 명시적 규칙을 사용합니다. 소비·승차 모형은 별도 참고 분석으로 제공하며 장소의 인기 점수로 합치지 않습니다.

판단 권한과 운영 통제

후보 탐색에는 계산량 제한이 있어 전체 관광지의 최적 코스를 보장하지 않습니다. 출처 정책을 읽지 못하면 추천을 중단하고, 실행 중 원본 수정·재학습·예약·결제는 하지 않습니다. 상담은 규칙과 준비된 문장을 사용합니다. 자료 갱신은 별도 검증 후 적용하며 런타임 LLM이나 유료 API 키를 요구하지 않습니다.

구현은 Python 표준 라이브러리, SQLite, JSON 모델, HTML·CSS·JavaScript입니다. 핵심 기능은 CPU와 오프라인 자료로 동작합니다. 근거 [2].

운영 중 정보가 부족할 때

위치를 받지 못하면 수동 기준 장소를 선택하고 출발지를 확인하도록 안내합니다. 출처 검사가 실패하거나 시간이 부족하면 이유와 조건 조정 방법을 표시합니다. 좌표 없는 기록, 배편·접근 문제가 있는 후보와 미지원 이동수단은 제한합니다. 공식 원문이 연결되지 않아도 기본 로컬 검색은 유지합니다.

공용 PC와 개인정보

GPS 위치는 동의를 받아 탭 메모리에서 사용합니다. 위치 변경·권한 철회·초기화·탭 종료 시 기존 경로를 무효화하고, 좌표 입력란과 HTML 저장에 비공개 위치를 남기지 않습니다. 수신 정밀도와 미확인 수신시각도 구분해 안내합니다. 저장 파일은 센터의 보관 절차에 따라 관리합니다. 센터 최소사양은 i7-8700, GTX1060, RAM32GB이며 현장 설치·성능 시험은 별도로 진행할 항목입니다.

자동 검증은 로컬 API와 모의 화면 기준입니다. 고정 공공장소 좌표의 28회 함수 검사는 실제 GPS 이동이나 현장 경로 정확도 시험이 아닙니다. 실제 브라우저·센터 PC 검수는 미완료입니다. 근거 [1], [2].

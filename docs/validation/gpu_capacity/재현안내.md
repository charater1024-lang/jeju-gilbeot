# GPU 상주 부하 시험 재현 안내

기록된 원시 결과는 2026-11-08 개발 PC에서 실행한 시험이다. 다른 장비에서 같은 수치가 나오는 것을 뜻하지 않는다. 센터 실측이나 향후 센터 방문 검증을 약속하지 않는다.

`실행원본`은 당시 코드와 경로를 그대로 보관한다. `재현도구`는 프로젝트 경로를 `JEJU_CAPACITY_PROJECT_ROOT` 환경변수로 받도록 바꾸고 종료 도구의 실행파일 확인 경로를 실행 소유 기록에서 읽도록 바꾼 사본이다. 측정·검증·부하 로직은 같다. wave에 관한 코드 주석만 명확히 했다. 원시 JSON protocol의 continuous/outstanding이라는 초기 설명은 각 wave 종료 후 다음 wave를 시작한 실제 구현으로 해석한다.

새 빈 작업 폴더에 `재현도구` 안의 파일들을 복사한다. 기록 보관 폴더에서 직접 실행하면 원시 결과를 덮어쓰므로 그곳에서 실행하지 않는다. 아래 명령은 새 작업 폴더에서 순서대로 실행한다. 실제 프로젝트 경로와 Python 경로는 설치 위치에 맞게 지정한다. Python은 Windows 표준 라이브러리만 필요하다. 앱은 프로젝트의 `runtime/python.exe`와 기존 모델을 사용한다.

```powershell
$env:JEJU_CAPACITY_PROJECT_ROOT='C:\실제경로\제주AI빅데이터활용'
$capacityPython='C:\실제Python경로\python.exe'
& $capacityPython .\launch_and_probe.py
& $capacityPython .\load_benchmark.py --part warmup
& $capacityPython .\run_all.py
& $capacityPython .\extended_test.py
& .\cleanup_test_server.ps1
& $capacityPython .\summarize.py
```

포트8791이 비어 있어야 하며, 도구는 기존 서버를 재사용하거나 종료하지 않는다. 시작 단계는 E5의 실제 DirectML 커널·GPU상주를 확인하며 준비 실패 시 중단한다. 종료 도구는 소유 PID·실행파일·명령행·포트가 일치할 때만 해당 시험 서버를 종료한다. 중간 실패가 생겨도 `cleanup_test_server.ps1`로 소유 서버를 정리한다. GPU 드라이버와 WDDM 성능 카운터 접근이 필요하고, 앱과 동일한 사용자 세션에서 실행한다.

확장 시험의 CPU affinity는 원래 값을 `finally`에서 복구한다. 이 시험은 12개 논리 CPU를 고르는 민감도 비교이며 센터 CPU나 GTX1060을 모사하지 않는다. 기존 모델·학습자료·서비스 임계값·연결 한도를 바꾸지 않는다. 실제 사용자 GPS와 외부 날씨 호출은 사용하지 않는다.

메모리 안전 중단값은 서비스 WorkingSet6GiB·전용VRAM2GiB·시스템 가용RAM8GiB다. 이 값은 앱에 상시 적용한 자원 제한이 아니다. GPU 표본 사이 순간 최고치는 포착하지 못할 수 있다. 요청 성공은 HTTP200과 기본 JSON/응답 구조 검사로 정의하며 추천 정답률을 보증하지 않는다.

동시 입력은 처리중+대기중을 포함한다. GPU 인코더1개가 batch1로 순차 실행하며, 실제 부하는 N개를 함께 시작한 뒤 그 묶음 전체가 끝나면 다음 묶음을 보낸다. 일정 도착률이나 동시 접속자 N명에 대한 보장이 아니다.

기존 `results/setup_trials/`는 초기 클라이언트가 8곳 결과를 3곳 기대값과 비교한 설정 오류를 보관한 폴더다. 집계33개 구간에서는 제외됐다. 재현 시 이 오류를 일부러 반복할 필요는 없다. `summarize.py`는 정상 완료된 33구간을 집계한다. 최종 기획서·보고서의 수치는 최초 보관 결과만을 근거로 한다.

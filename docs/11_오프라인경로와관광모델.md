# v5 장소 상세·오프라인 경로·관광 모델

2026-10-28. 센터 PC에서 CPU로 실행하는 로컬 웹사이트다. 기존 6개 사진의 5초 전환과 음식·소비·승차 기능을 유지했다.

## 이용 흐름과 수정

‘장소 자세히’가 선택 강조만 갱신하던 문제를 실제 상세 대화상자로 수정했다. 대표 관광지·확장 관광지·허브 장소·음식 기록에 같은 상세 API를 사용한다. 주소·좌표·편집일·수집일·분류를 보여 주며 영업시간·전화·휠체어·이용료·웹사이트는 해당 태그가 실제 있는 경우에만 표시한다. 사진이 없는 장소는 위치 배너를 사용한다.

관광지 찾기 → 상세 보기/여행에 담기 → 담은 장소로 경로 만들기 → 내 경로에 맞춤 순서로 이용한다. 최대 8개 장소를 저장한다. 목록은 24개씩 추가하며 현재 검색 결과 중 최대 500개를 지도에 표시한다. 테마·지역·분류·기준 장소 반경·현재 지도 범위를 지원한다. 묶음 숫자에서 가까운 장소를 고를 수 있다. 오프라인 지도에서 확대·축소·끌기·방향키·선택 장소/경로 맞춤을 제공한다.

기본 관광 목록은 10+1,138=1,148개다. 관광 분류가 확인되지 않은 허브 명부는 별도 선택한다. 출처별 중복 장소가 있을 수 있어 물리적 고유 관광지 수로 해석하지 않는다. OSM은 공동 편집 지도이며 현재 운영을 확인한 공식 관광시설 전수조사가 아니다.

새 원본은 `data_raw/osm/jeju_tourism_v5.json`(737,044바이트), `jeju_roads_v5.json`(34,524,993바이트)이다. 기준 시각은 각각 2026-10-28T12:14:10Z / 12:16:18Z다. 개별 장소 편집일과 수집일을 구분한다. 같은 폴더에 SHA·질의·수집 주소·ODbL 고지를 보존했다. 기존 허브 CSV 8파일(독립 ID 7개, 512,511,909바이트)은 최종 작업 폴더에 보존한다. 기존 제출/재배포 확인 상태는 유지하며 실행 ZIP에 허브 CSV를 넣지 않는다.

## 실제 활용 모델

| 모델 | 학습 자료 | 활용 |
|---|---|---|

| 음식 TF-IDF | 인허가 20,954 + 독립 OSM 6,102 = 27,056개 문서 | 음식어와 업소명·업종·존재하는 cuisine 태그 관련도 |
| 집단 소비 구성비 | 2018-01~2025-06, 90개월 / 1,440개 월·집단·업종 셀 | 과거 8업종 구성비 |
| 승차 패턴 | 2023-12-25~2025-10-26, 672일 / 4,704개 날짜·시간대 셀 | 요일·시간대별 시간당 일반승차 |
| 합성 방문량 체험 | 합성 POI·날짜 5,340행 | 구분해서 제공하는 개발 체험 |

관광 TF-IDF는 이번 확장 자료로 학습해 `models_tourism/tourism_tfidf.json`과 `data_reference/tourism.sqlite`에 저장했다. 문서빈도·IDF·정규화 벡터를 실제 말뭉치에 맞춘 비지도 검색 모델이다. 동의어·분류 우선순위·직선거리 정렬은 별도 명시적 규칙이다. 관광객 만족도·개별 장소 방문량을 정답으로 학습한 인기도 예측은 아니다. 새 모델의 현재 개발 PC 학습 시간은 약 0.425초이며 센터 최소사양 실측이 아니다.

소비 계절 후보의 검증 MAE 0.01601372보다 집단 평균의 0.01593516이 나았다. 승차 Ridge의 109.9577명/시간보다 요일·시간대 평균의 86.4884명/시간이 나아 해당 평균 모델을 서비스한다. 후보의 결과도 보존한다. `/api/models-info`와 화면 모델 카드는 실제 저장 프로필·검증 결과에서 학습 여부·자료 수·기간·한계·사용 기능을 읽는다. 관광 카드와 상세창은 겹친 실제 학습 표현을 보여 준다. 사람의 추천 만족도 평가 데이터가 없으므로 추천 정확도 수치를 만들지 않는다.

## 경로 계산과 표시

OSM way의 실제 node 연결에 A* 최단거리 탐색을 적용했다. 일방통행·역방향·회전교차로 방향, 명시적 차량 접근 금지·사유지, 일부 장벽을 반영한다. 가까운 별도 도로를 임의로 이어 붙이지 않는다. 장소에서 최대 1.5km 이내의 도로 node를 찾아 실제 연결될 때만 실선을 제공한다. 방문 번호·방향·출발/도착점을 표시한다. 도로까지의 짧은 점선은 실제 입구를 확인한 연결이 아니다.

회전 제한 relation·실시간 통제·교통속도·공사·주차장 진입·페리·보행전용 탐방로는 수집 범위에 없다. 법적 통행과 현재 운행을 보장하는 내비게이션이 아니다. 봉우리·화산·동굴 등 입구 확인이 필요한 OSM 410개 기록 및 배편 필요 장소는 자동차 일정에서 제한한다. 도보·도로 단절 등에서는 방문 순서 점선임을 명시한다. 일정의 시간·이동비는 기존 거리 기반 계획 추정이며 새 도로 경로의 실시간 소요시간과 같지 않다.

공항→함덕→성산→공항 예시는 약 95.21km / 도로 좌표 2,726개다. 초기 그래프 로딩 포함 약 0.939초는 개발 PC 측정이며 센터 장비 성능 보장이 아니다.

## 실행과 위치

사진·SDK·검색 색인·모델·해안선·주요 도로선·도로 그래프를 로컬에 넣었다. 실행 중 API 키·LLM·GPU·pip 설치가 필요 없다. 온라인 지도는 사용자가 선택할 때만 타일에 접속하며 대량 타일 저장을 하지 않는다. 기기 위치는 사용자가 버튼과 브라우저 권한을 선택했을 때만 로컬 거리 계산에 사용하며 파일·모델·일반 요청 로그에 저장하지 않는다. 사용자 출발/도착 좌표가 포함된 경로와 연결선 전체는 온라인 지도에서 제외한다. 위치를 지워도 그 경로의 비공개 표시는 유지한다. 공개 장소만 탭 세션에 저장하며 새 여행 시작으로 초기화한다.

## 재현과 검증

원본·정규화 자료가 있는 개발용 Python에서 `python scripts/build_tourism.py`, `python scripts/build_roads.py`로 재생성한다. 자동 다운로드 도구는 원본이 있으면 다시 받지 않는다. `python -m unittest discover -s tests -v`, Node의 `tests/ui_map_v5.cjs`, `ui_tourism_v5.cjs`, `ui_location.cjs`, `ui_itinerary_export.cjs`를 실행한다. 서버 기동 후 HTTP 검증은 `tests/http_smoke_v5.py`의 도움말을 따른다.

검증 로그·HTTP 결과·데이터 감사 JSON을 이 폴더에 보존했다. 실제 브라우저에서 장소 상세·테마 검색·추가 표시·음식 검색·두 장소 경로·390px 가로 넘침을 확인했다. 실제 기기 GPS 권한과 센터 최소사양 실장비는 현장 확인 항목이다. ZIP에는 휴대용 Python 표준 라이브러리 `runtime/python313.zip`까지 포함하고 클린 압축 해제 실행을 확인한다.
